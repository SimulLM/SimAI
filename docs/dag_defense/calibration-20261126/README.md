# Request-level calibration collection

A fresh vLLM 0.8.5 FP16 TP1 1P1D service was started on the two H800s with prefix and chunked prefill disabled, an 8 GiB KV buffer and the streaming router. The intended calibration matrix is input 512/output 64, serial and waves of two, 32 requests per mode and three repeats. The first collector implementation emitted only 16 serial requests per repeat and 32 concurrent requests; a separate serial supplement emitted the missing 16 serial requests for each repeat. The merged set contains exactly 192 successful requests: 3 repeats × (32 serial + 32 concurrent2), all with 512 prompt tokens and 64 generated tokens, EOS ignored, temperature 0, seed 0. Client and router timestamps, backend IDs, token counts and output usage are retained. No cost fitting was performed from these completion times.

The request-level summaries show serial E2E medians around 0.838–0.843 s and concurrent2 medians around 0.865–0.871 s; serial TTFT medians are about 0.042–0.043 s and concurrent2 about 0.068 s. These numbers include the streaming router/API boundary and are calibration diagnostics only. The router server was stopped intentionally (exit 143). A preceding launch attempt failed from an orphaned profiling process exhausting GPU memory; that failure remains in `raw/server-launch.log` and was resolved by terminating the identified profiling process before retrying. No validation request was run.
