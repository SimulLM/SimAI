# PD connector buffer and model-step diagnostic

The vLLM 0.8.5 PyNcclConnector default `kv_buffer_size=1000000000` deadlocked on a four-request 512-token wave: all four clients timed out after 30 seconds. The prefill path waits for all producer responses before the proxy starts decode, while the producer buffer blocks insert when full. A 512-token Llama-2-7B FP16 KV payload is approximately 256 MiB per request, so four items exceed the default limit. This diagnosis is supported by the buffer backpressure source and the observed wave behavior; the timeout is retained in `raw/buffer1g-b4-timeouts.jsonl`.

An explicit 5,000,000,000-byte connector buffer allowed the four-request smoke to return four HTTP 200 results. A separate synchronized diagnostic then issued 840 successful short PD requests across input lengths 512, 1024, 2048 and wave sizes 1, 2, 4, with 10 warmup and 30 measured waves each. Actual batch size can differ from wave size, especially at 2048 tokens due to max batched tokens. The outer CUDA event includes asynchronous execution and a synchronization after each model step. Raw events and client metadata are preserved; the exact measurement-to-request mapping and warmup exclusion must be validated before adopting costs. The diagnostic client is not the formal streaming router and these measurements are not validation E2E.

A 32-request calibration replay with an earlier preliminary real PD profile and CPU overhead skipped yielded medians near the actual median. It remains a diagnostic only. No parameter freeze or 960-request validation has been performed.
