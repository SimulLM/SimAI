# Collector failure exit and restart marker

Previously, when a request failed or timed out, the collector recorded its wave and marked later inputs not submitted but returned process exit 0. That could mislead a service supervisor into reusing an unsafe instance; the separately captured pre-response cancellation diagnostic showed a producer connector item remaining after a client disconnect.

The collector now durably writes `restart-required.jsonl` with the failed wave and counts before marking later requests not submitted, returns `incomplete_restart_required`, and its command-line invocation exits 1. A successful client collection returns exit 0 but still requires separate server reconciliation and idle verification. The collector does not itself stop the server, and does not certify state after exceptions or external interruption; a service supervisor must stop the instance on any nonzero exit or abnormal termination and re-establish readiness before another run. Formal orchestration and readiness remain open.

Local synthetic service tests exercise 32 successful requests; HTTP failure with 30 later unsubmitted; timeout with 28 later unsubmitted; and an actual collector CLI process that receives injected 503 responses, returns exit 1, preserves two failed and 30 unsubmitted rows, and writes the restart marker. The asynchronous slow/failed writer test was run directly because pytest is not installed in the vLLM Python environment; the initial failed pytest invocation did not alter the environment. The tests do not issue GPU requests or replace the real cancellation evidence in `pre-response-timeout-recovery-20261126`. Formal validation remains 0/30.
