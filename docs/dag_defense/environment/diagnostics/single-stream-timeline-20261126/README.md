# One streaming request with worker host events

A real repeat of the first 512/64 calibration input after one warmup used the candidate streaming router, greedy decoding and a lightweight worker hook with no explicit GPU synchronization. The saved audit joins the stable client request ID to the router and producer/consumer worker IDs, checks output count, KV bypass, one producer step, 64 consumer steps and host timestamp order. The measured router interval was 0.880765463 s and client interval 0.881616625 s; this is one instrumented diagnostic repeat, not the original calibration request or a validation measurement. Both GPUs were released after shutdown.

`events.jsonl` preserves same-run CLOCK_MONOTONIC router and worker host timestamps, batches and raw request identifiers. Producer and consumer model-step starts/returns and connector send/receive API starts/returns are CPU-side events; none is a GPU transfer completion or exact KVReady. This hook's overhead has not been quantified, and the trace does not identify network transfer start/end, queue causes, or GPU completion. Thus the single-request cost and event-alignment gates remain open. The detailed synchronized repeat remains separate. Full responses, launcher, service logs and exit code are archived; no validation or cost fitting was performed.
