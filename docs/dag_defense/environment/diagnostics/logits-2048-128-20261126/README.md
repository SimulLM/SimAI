# 2048/128 Decode logits instrumentation supplement

A new actual FP16 TP1 1P1D dual-H800 profiling run issued 40 waves of four requests (10 warmup, 30 measured). All 160 completed with 2048 input and 128 output tokens; client and launcher exited 0, both GPUs released. The producer and consumer used vLLM 0.8.5 eager with the existing accounting instrumentation, which adds CUDA event hooks and device synchronization. This is a fee diagnostic, not formal E2E validation.

The audit maps all 160 backend IDs, verifies exactly 127 subsequent Decode events for each, and deduplicates 5,111 actual batch steps by worker PID and host start time. It groups by **actual** batch size, wave and four 32-token bins based on the maximum sequence length in each batch. Batch members can have different contexts; bins do not prove uniform context. Batch 4 had all 10 warmup and 30 measured waves represented in each of the four bins; median wave-median logits GPU event intervals were 0.147200, 0.147264, 0.147272 and 0.147264 ms. Other actual batch sizes and their coverage are in `audit.json` and `wave-logits.csv`. The separate 8-output run's 29-wave batch-4 shortfall is not retroactively overwritten; this is a new 128-output session.

Events can include idle gaps, the instrumentation perturbs timing, all waves share one service session, and measured GPU logits intervals may overlap host sampler wait. No claim of standalone additive wall time, full 1024/2048 matrix coverage or final cost freeze follows. Source script, client, full service/client logs, raw events and exit are in the hashed archive `/root/autodl-tmp/dag-handoff/logits-2048-128-20261126-raw.tar.gz`; the instrumentation and client source are in `pd-accounting-20261126`. Formal validation remains 0/30.
