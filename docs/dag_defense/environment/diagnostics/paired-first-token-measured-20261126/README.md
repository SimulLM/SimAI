# Measured first-token cost in a fixed two-request diagnostic

CPU-only synthetic simultaneous 1024-input, 128-output two-request replay. A separately readiness-corrected, fixed-batch modified baseline and experimental DAG share the same original predictor hash and use the same explicit first-token post-sync host fee of 0.912567 ms once per group. This fee is the median of 30 actual 1024/requested-concurrency-2/actual-batch-2 first steps from `concurrent-paired-boundaries-20261126`; that stratum has only seven warmup waves and extensive synchronization, so it is a diagnostic candidate, not a qualified frozen production fee. The baseline and DAG have different transfer scheduling. The DAG assigns the inclusive host interval GPU resource demand while the modified baseline barrier does not reserve a GPU; this is not a validated general concurrent resource equivalence.

Both executions exit zero and submit and complete one shared first-token operation after all modeled KV arrivals. Both perform exactly 127 subsequent decode steps per request. All 128/128 modeled batches pair on stage, membership, per-request history and token counts; matched modeled batch costs differ by less than 1 ns. This comparison tests a fixed group and the shared first-token accounting rule, not the untouched original, natural batches, all fee shapes, physical receive timing or real E2E. The first-token task is outside the 128 model-batch comparison, its fee is checked separately. Existing predictor and PD transfer costs are not proven nonoverlapping with the host interval. Validation remains 0/30.
