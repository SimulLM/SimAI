# Independent two-concurrent calibration

Previous two-concurrent calibration had 32 requests per repeat with non-overlapping client waves, but the next repeat followed other traffic with less than one millisecond gap, leaving no demonstrated idle boundary. Three fresh vLLM 0.8.5 eager 1P1D service starts each ran two 2-request warmup waves and then sixteen 2-request measured waves at 512 input/64 output, with each wave waiting for the preceding wave to complete. All 108 requests including warmups had expected lengths, unique saved token arrays, matching router/backend IDs and valid host event order. All three services stopped with both GPUs showing zero memory use afterwards. Separate starts and client wave boundaries do not prove internal KV cleanup immediately after warmup.

The three measured median router E2E times were 1156.468, 898.022 and 1299.162 ms; do not present as stable. The 1 Hz GPU telemetry records utilization, SM/memory clock, power and temperature. Median sampled SM frequency was 1755 MHz on both GPUs in all three repeats; sampled temperature and frequency ranges are in telemetry-summary.json. This does not establish the cause of latency variation: one-second samples may miss short changes and were not directly aligned to monotonic request timestamps. Keep all outliers. Prior serial calibration also varied and had no per-request telemetry. Original logs, individual input tokens, service events, telemetry, commands and checksums are preserved. Formal validation remains 0/30; GPU/CPU/KV cost overlap and service/simulator scheduling compatibility are not frozen.
