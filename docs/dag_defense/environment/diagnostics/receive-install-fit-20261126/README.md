# Synchronized receiver interval sensitivity fit

An affine candidate was fitted only to the independent 512/1024/2048 serial receive-through-install-synchronization samples. Even/odd measured waves were split into 45 fit and 45 holdout samples; the split-fit is 4.5052672 ms + 0.0157274221 ms per input token. Held-out mean absolute errors are 0.864, 0.566 and 0.810 ms respectively (15 points per length). All-sample coefficients are provided separately in summary.json. Source sample SHA-256 and each holdout prediction are saved; no validation request or request E2E duration was used.

The 255 Gibit/s candidate transfer cost alone differs by about 4.87–5.20 ms on these holdout samples, but it measures a different boundary and excludes paged KV installation. This comparison identifies a boundary mismatch, not a valid claim that one cost model predicts production better. The new source uses per-tensor device synchronization and includes control, matching, Python, waits, transport and KV installation. Split samples come from the same service session; concurrent batch behavior, noninstrumented timings, CPU/GPU resource overlap and baseline integration are unverified. The fitted intercept is an effective synchronization-contaminated interval, not physical latency. This is an explicitly separate sensitivity candidate and is not frozen or used as the common original/DAG fee. Formal validation remains 0/30.
