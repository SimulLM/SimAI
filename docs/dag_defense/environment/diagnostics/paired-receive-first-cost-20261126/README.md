# Paired receive-to-first-step cost boundaries

Reanalysis of existing `receive-install-interval-20261126/samples.csv`: 512, 1024 and 2048 input tokens, each 10 warmup and 30 measured serial eight-output real PD requests. For each same request, the audit verifies `receive_start <= install_sync <= first_step_return` on the shared host monotonic clock, and records paired receive-to-sync, post-sync-to-step-return and combined intervals. The combined measurement is one indivisible inclusive candidate; KV installation is inside it and must not be added again. Per-request rows, summary and source SHA-256 are preserved.

Measured combined interval medians are 12.973653 ms (512), 21.302509 ms (1024), and 37.256629 ms (2048). This is not the sum of independently selected medians: each combined sample is calculated from its own timestamps. The separate receive and post-sync measurements can be used as diagnostic subintervals only, not added to the combined amount. A candidate that also charges an effective-bandwidth transfer, KV installation or post-KV sampler on top of this combined interval would duplicate recorded work.

This scope starts at the consumer connector host call, not router arrival or Decode dispatch; it ends at first-step host return, not streaming first-token delivery. Per-tensor device synchronization and detailed hooks change the real asynchronous overlap. These serial eight-output samples do not establish concurrent first-step cost, 128-token wave behavior, production wall-clock additivity or a universal simulator fee. The three lengths share one service session. No validation completion time was used and no fee was frozen. The existing default simulator path remains unchanged.
