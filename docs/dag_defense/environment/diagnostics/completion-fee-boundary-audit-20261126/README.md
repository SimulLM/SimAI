# Completion and fee boundary audit

Status: **open**, not a formal validation or a fitted correction. This audit combines existing raw request events with inspected vLLM 0.8.5 and simulator code; no new GPU run or E2E-derived fee was made.

| Item | Actual recorded meaning | Simulation or fee mapping | Remaining evidence |
|---|---|---|---|
| Server arrival | Router logs CLOCK_MONOTONIC after FastAPI enters the completion handler, before parsing JSON. | Request trace must use this router arrival, not client send. | Preserve per-request clock, mapping and failures for every validation run. |
| Final generated token | vLLM builds a stream chunk from generated `output.token_ids`, increments token count, and yields the chunk, including `finish_reason` when present (serving_completion.py:265–364). | Last Decode model batch increments processed tokens; request is marked complete at that batch end (`request.py:258–301`). | The simulator event does not itself include all frontend emission and transport. A worker model-step host return is not a GPU completion event. |
| Router completion | Router yields every backend line, then emits `server_complete` only after backend iterator ends with `[DONE]`, a request mapping and non-null usage (pd_stream_proxy.py:35–56). vLLM yields the final usage chunk and `[DONE]` after the result generator ends (serving_completion.py:367–392). | Simulation completion is the last modeled batch end; the router post-batch tail is not separately identified in its cost graph. | After `yield`, resumption indicates the ASGI send call returned, not proof the remote client received every byte. Failures and cancellation are logged separately. A tail estimate must not be added until its overlap with existing CPU/output fields is measured. |
| Sampler | Synchronized sampler host interval includes sampler GPU work and waiting. | Candidate v5 maps that inclusive interval once to sampler_e2e. The whole-forward CUDA profile excludes logits and sampler; the separate consumer-first-token candidate includes them in its own interval. | Show per-step invocation and scope so first-token sampler is not also charged as a normal decode sampler; establish overlap with other host fields. No assumption that synchronized latency equals production latency. |
| Output processing | `_process_model_outputs` host-call timing and scheduler/preparation calls are separate profiled host scopes, but do not cover frontend serialization and all IPC. | Candidate predictor maps them to their respective CPU fields. | Prove which GPU work is awaited in host calls, account for logits/head and verify the router tail is outside current charged intervals. Do not assume all host and GPU intervals sum without overlap. |
| KV receive and install | Serial diagnostic synchronizes after individual tensors; fitted receiver candidate covers receive, wait and install in one host interval. | Replaces the old equivalent-bandwidth transfer task in the diagnostic; does not add a second KV install fee. | Determine production overlap and waiting under normal asynchronous operation and concurrency before using it as frozen transfer cost. |

Ninety 512/1024/2048-input, eight-output real diagnostic requests joined by router and worker ID show last consumer model-step host return to router completion medians 1.0027/0.9974/1.0606 ms and p95 1.2470/1.2795/1.2567 ms. The hook uses per-tensor synchronization and short outputs, and host return can precede GPU completion. These observations bound neither the standalone CPU fee nor production 512/64 or 128-output behavior. See `last-step-router-boundary-20261126/requests.csv` and its README. Across 192 separate 512/64 calibration requests, router completion to client completion median was 0.185 ms, p95 1.197 ms, maximum 98.100 ms; possible blocking client fsync was not timestamped. See `calibration-client-router-boundaries-20261126`.

The forward-only replay is a sensitivity experiment and its single-request success does not establish unbiased total cost or concurrent scheduling. The pristine baseline and predictor-adapted baseline remain distinct. Freeze and 30 validation rounds remain blocked on these semantics, controlled two-/four-request checks, and an independently justified common cost mapping.
