# Existing calibration router boundary audit

Reuses existing real eager vLLM 1P1D calibration: 512 input/64 output, three repeats each of serial and concurrent-two, 32 requests per repeat. All 192 client IDs map to exactly one router arrival, prefill send/response and backend mapping, decode send/mapping, first-token and completion event; ID consistency and required host event ordering pass. Router first-token is observed from streamed usage, and server completion is the router's stream completion; both are host boundaries. The 96-request serial median server E2E was 840.321 ms and concurrent-two median 866.975 ms; these are descriptive calibration observations, not fees or validation results. See request CSV and audit for each interval and source hashes.

This does not prove GPU KVReady, isolate CPU/GPU costs, prove idle state before each repeat, or resolve server-versus-simulator scheduling. Some serial requests came from a separate supplement; retain provenance and verify before declaring final calibration. No costs were fitted to validation data. The original raw client and router logs remain in the documented calibration directories, and the prior 2% comparison remains invalid. Formal validation remains 0/30.
