# Single-request same-fee first-token mechanism comparison

A separate worktree starts from pristine baseline commit cef83f9ddd96540e3e9f48934f11335d52d54fce. The predictor adaptation and the additional diagnostic stage are separate saved patches. The original checkout and previous predictor-adapted baseline are preserved. Set SIMAI_SERIAL_FIRST_TOKEN_S and SIMAI_SERIAL_FIRST_TOKEN_TRACE only for the documented diagnostic run. The modified simulator rejects any trace containing more than one request; an actual 32-request CLI invocation verified that guard. The baseline's event waits for the measured interval before scheduling Decode, but it does not reserve a GPU resource. With exactly one request and no competitor, this is a timing-mechanism check, not a concurrency model.

For the isolated 512/64 calibration input, both diagnostic versions use the same independently measured 0.000875779 s host interval and identical candidate computation/communication inputs. The baseline records first-token start 0.03125546923365413 s and end 0.03213124823365413 s. Diagnostic baseline and DAG complete at 1.0534134097541064 s and 1.0534134097540713 s, respectively. The earlier predictor-adapted baseline without the stage is retained at 1.0525376307541063 s. The audit checks event count, dependency time, fee, input/output length and completion. This equality validates serial fee accounting only; neither this interval nor the overall model has been frozen or validated as physically exact.

An initial attempt enabled the original baseline JSON trace and returned exit 0 even though an atexit exception left invalid truncated JSON because a set was not serializable. The failure log is preserved; the successful repeat disables that trace and writes only the diagnostic event to JSONL. This is not an untouched original-baseline result, a concurrency test, a formal validation, or an accuracy improvement claim.
