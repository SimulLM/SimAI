# Exploratory Decode-pull source-batch sensitivity

The prior real 8-output-token diagnostic showed the first consumer receive often spanning a subsequent producer Prefill host interval. In the 30 measured waves for 1024/concurrency 4 and 2048/concurrency 4, all had a later Prefill step whose host interval overlapped the first receive; for 2048/concurrency 2 this was true in 29 of 30. These are host-clock intervals from synchronized instrumented execution, not proof of exact GPU kernel overlap, causation, or transfer resource occupancy.

Two opt-in simulation approximations were added, preserving legacy defaults. Schema 1.3 allows a nonnegative fixed dispatch delay for candidate pull mode; the selected sensitivity uses the separate instrumented serial medians from Prefill after-sync to consumer step start: 4.5259245 ms at 1024 and 6.3988115 ms at 2048. That interval includes scheduling and instrumentation, so treating it as a fixed delay is a hypothesis, not an isolated cost. Schema 1.4 optionally defers pull initiation while the source replica has an already running Prefill batch, approximating whole-batch stream ordering. It may over-serialize CPU/GPU work and is not a measured GPU-exclusive interval. The common compute and communication fee inputs are unchanged; baseline is the previously adapted comparator.

The first delay-only sensitivity accidentally supplied two conflicting `--dag_pd_config` arguments, and the latter pointed to the old zero-delay config. That run is preserved and provides no delay conclusion. The corrected run verifies both arguments select the intended case config and checks migration timestamps. All six corrected DAG runs exited 0. Relative to the existing six selected real waves, delay alone did not change Decode memberships. With delay plus source-batch waiting, the per-request step membership matches in concurrency-2 cases changed 8/14 to 12/14 at 1024 and 6/14 to 14/14 at 2048; concurrency-4 changed 4/28 to 28/28 and 3/28 to 23/28. Serial cases remained 7/7. These are exploratory fits on the same six selected instrumented waves used to investigate the hypothesis, not independent validation or an experiment-wide score; neither batching identity nor improvement is a plan acceptance threshold. The adapted-baseline outputs were copied from the prior identical-arrival replay and not rerun. Effective input/output lengths were verified.

46 focused PD tests pass, including dispatch gating, source wait, resource cleanup and old configuration compatibility. Source-batch waiting occurred 0 times in serial and 1,1,1,2 times in the four concurrent waves. Full traces, configurations, the incorrect run, logs, scripts and audit output are preserved in the archive referenced in `raw-archive-sha256.txt`. The candidate requires independent calibration, overhead/non-overlap and real queueing checks, and full validation-shape coverage; the 512-token calibration delay has not been established. No parameter freeze or formal validation occurred (0/30).
