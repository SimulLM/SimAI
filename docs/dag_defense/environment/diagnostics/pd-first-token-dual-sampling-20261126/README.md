# First-token operations at both PD endpoints

Reuses the independently captured instrumented 512-input/8-output serial 1P1D run (10 warmup, 30 measured requests). All 40 requests map uniquely from client/router to producer and consumer, complete with expected length, and show one producer model step with logits and sampler, one consumer KV-bypass prompt step with logits and sampler, and seven subsequent consumer Decode forward steps. The producer's sampled response is used by the router to trigger Decode; the consumer produces the streamed output. Request-level mappings and timings are preserved in `requests.csv`; no new GPU requests were issued.

Measured medians in milliseconds: producer logits CUDA event 0.167, producer sampler CUDA event 0.364, consumer logits CUDA event 0.155, consumer sampler CUDA event 0.354; producer sampler host call 0.643 and consumer sampler host call 7.230. These intervals overlap or may contain asynchronous device waiting; they are not additive component costs. Synchronization, hooks and the 8-token diagnostic can alter timings. The result demonstrates operations at both endpoints but does not identify a non-overlapping incremental first-token cost, establish GPU completion at host return, or prove the distribution at 128 outputs.

The simulator Request lifecycle accounts for one output during Prefill and seven following Decode steps in this eight-token setting, while the observed service streams its first output after consumer KV bypass. The candidate simulator has per-stage sampler overhead, but no separately validated consumer KV-bypass first-token stage. This is a boundary mismatch to resolve through a measured, non-overlapping cost contract; directly adding consumer host and CUDA medians would risk double counting. The same cost semantics must be applied to the adapted baseline and DAG for the common-fee comparison. Existing raw event files and SHA-256 hashes are referenced in `summary.json` and archived in sibling `pd-dispatch-512-independent-20261126`. No validation data were used; formal validation remains 0/30.
