# Real 1P1D stable request ID smoke

On the new dual-H800 server, the candidate router from `environment/scripts/pd_stream_proxy.py` served one real 512-input/64-output streaming request through the existing vLLM 0.8.5 FP16 TP1 1P1D deployment. The request completed with expected token counts and backend ID. The server-arrival event contained the supplied `correlation-smoke-req0` client ID and the returned router ID and Decode backend ID were consistent. This checks successful-path correlation only; early timeout correlation was tested with a local fake backend in the sibling `validation-correlation-20261126` checkpoint, not in real GPU service.

Service logs, router events, startup and client scripts, probe observations and exit codes are in the archive recorded by `raw-archive-sha256.txt`; `router-sha256.txt` identifies the router source used. The auxiliary idle probe returned 2 because connector state is not certified; this does not negate request completion. Both GPU memories were zero after service stop. This is a diagnostic smoke, not calibration or validation. Costs, scheduling, warmup/idle orchestration and complete event semantics remain unresolved; formal validation remains 0/30.
