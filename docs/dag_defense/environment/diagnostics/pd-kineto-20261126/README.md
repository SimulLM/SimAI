# Producer GPU Kineto traces for real 1P1D

Separate PyTorch/CUPTI profiler diagnostic, not formal E2E. Actual vLLM 0.8.5 eager FP16 TP1 1P1D, 4 requested concurrent requests per wave, output 8 tokens, non-streaming diagnostic router; profiler active on producer worker for 28 prefill execution calls after two warmup calls. Client ran 20 waves at input 2048 (80/80 HTTP 200) and 26 waves at input 1024 (104/104 HTTP 200). Profiling stopped and exported during the client run, so not every request lies in the trace. Raw traces, router and client logs, profiler control, source and commands are retained; both GPUs released.

All GPU0 kernel events in the 1024 trace used CUDA context 1, stream 7: 371 NCCL and 15241 non-NCCL kernels. Audit found no timestamp-overlapping NCCL/non-NCCL kernel intervals. The 2048 trace had 261 NCCL and 13573 other GPU0 kernels, also all context 1, stream 7. Three kernel interval pairs have apparent timestamp overlaps of at most 0.384 microseconds, despite sharing a stream; these tiny boundary overlaps are not evidence of concurrent kernels and can reflect timestamp resolution/recording artifacts. NCCL classification is by kernel name and no per-request tensor mapping is asserted. Chrome-trace timestamps use microseconds and are not converted to the host monotonic clock.

This supports serialized source GPU kernel execution in the captured diagnostic windows. It does not establish exclusive resource ownership of both GPUs for a complete transfer, transport thread CPU overhead, all workload shapes, or uninstrumented behavior; profiler and synchronous export perturb execution. The previous CUDA-event interval overlap did not prove simultaneous kernels because event intervals include launch gaps and stream waits. Direct NCCL synthetic microbenchmarks used a separate compute stream and are not equivalent to this service. Do not infer a final `occupies_gpu` setting or freeze costs from these traces alone. Formal validation remains 0/30.
