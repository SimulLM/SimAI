# Receiver transfer plus KV installation interval

Reanalysis of the same 120 real serial requests in `serial-kv-install-20261126`, with 10 warmup and 30 measured requests per input length. For 512, 1024, and 2048 tokens, the consumer host interval from entry to receive/cache-install routine until post-install device synchronization has medians 12.2654, 20.5336, and 36.3565 ms. Per-request IDs, timestamps, ranges and p95 are retained in samples.csv and summary.json.

The installation interval is wholly inside that receive-to-sync interval: do not add it again. The subsequent post-sync-to-first-step-host-return interval is separately timed, but it does not encompass all router or scheduler work. These are inclusive host intervals including waiting, Python and device synchronization, not isolated physical kernel costs. The diagnostic synchronizes each transmitted tensor, changing service overlap and scheduling; samples cover serial requests with 8 outputs, not concurrent batches or production E2E. Independent SimpleBuffer-only microbenchmark timings use different boundaries and must not be added to the combined interval. No candidate was frozen or fitted to validation.
