# First transfer resource divergence and sensitivity

CPU-only replay of the same instrumented real-arrival 2048/8 four-request wave as `fixed-groups-resource-20261126`. The DAG cases use identical source, arrival trace, first-token fee and configuration except `occupies_gpu` (and its evidence label). The fixed-group baseline is modified, not pristine. Both DAG alternatives are modeling hypotheses, not upper or lower physical bounds. No final validation or E2E-based fee fitting occurred.

The first Prefill batch ends at 83.053 ms on both sides. The next Prefill starts at that time on both sides but finishes at 212.954 ms in the modified baseline versus 243.344 ms in the DAG with transfer GPU occupation enabled. The DAG's layer-0 attention task waits 30.390 ms for GPU 0 while the first KV transfer occupies it until 114.441 ms. Later Prefill accumulates another 62.144 ms of GPU wait. The baseline has no comparable source GPU reservation during transfer. Thus this candidate resource rule explains the first Prefill timing divergence; it is not evidence the hardware necessarily serializes those operations.

Disabling DAG transfer GPU occupation makes all three Prefill start/end times equal to the modified baseline on this wave. However, the resulting Decode histories differ: 10 of 22 baseline batches and 10 of 17 DAG batches match, all paired costs within 1 ns. First Decode membership divergence at position 6 is baseline [0] versus DAG [0,1,2]. Request 0 finishes at 298.223 ms rather than 232.112 ms under the GPU-occupied candidate, while request 3 finishes at 460.597 ms rather than 549.912 ms. Scheduling and batching change, so these are not independent fee deltas. Both candidates use identical group fees but are not the pristine original comparison.

`compare.py` checks matching trace/fees, exact configuration differences, Prefill endpoints and records the task-level waits; `audit.py` checks group counts, readiness, token steps and matched batch costs. Source files, logs, first-token and task traces, and failed/alternate data are retained in the hashed archive and prior linked evidence. Measured SimpleBuffer contention diagnostics show substantial contention in their controlled setup but do not establish exclusive occupancy for the service; preserve that limitation rather than select a model merely for lower error. Next, choose a defensible common execution model and report its limitations; actual natural workloads can create different batches and cannot inherit this pairing ratio.
