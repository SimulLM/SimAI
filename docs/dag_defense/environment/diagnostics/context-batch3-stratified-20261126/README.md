# 1024-token batch-three composition and wave variability

Reanalysis of the previously captured `pd-context-batch3-20261126` synchronized real dual-H800 1P1D profile; no GPU run and no validation completion data. Eight 16-token mean-context bins each contain 20 warmup and 40 measured distinct requested-batch/wave observations after allowing observed actual batch 3 with either all sequence lengths equal or a maximum difference of one token. One median per wave is used; a wave is never counted twice merely because it contains several steps. Grouping the two compositions defines a broader candidate fee point; it does not make either individual stratum satisfy 10/30. Measured strata contain 14 uniform and 26 mixed waves per bin. Source hashes, wave identities, counts, and per-wave medians are in the audit and CSV files.

Across bins, pooled medians are 15.119–15.304 ms and the absolute difference between the two descriptive stratum medians is 0.15%–1.04% of the pooled median. Some p95 values reach 28–30 ms and maxima 31–33 ms. Preserve these waves: no filtering or assumption of statistical equivalence. Strata are not randomized, share one service session, and may reflect other scheduling state; the observed difference is not a causal estimate or a universal bound. Per-step CUDA synchronization affects scheduling and measured forward can include stream gaps. This scope excludes logits, sampler, CPU, KV and router; it replaces rather than supplements layer forward compute. Arbitrary mixed context, other missing shapes, first-token, concurrency and additive cost boundaries remain open. The pooled values are an explicitly composition-specific candidate, not a frozen production cost; formal validation remains 0/30.
