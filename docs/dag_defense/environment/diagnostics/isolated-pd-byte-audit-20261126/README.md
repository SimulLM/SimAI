# PD bytes and charging in the isolated 512/64 candidate replay

The adapted baseline computes its request PD bytes from `num_processed_tokens`, asserted to be Prefill tokens plus one in `events/batch_end_event.py`. At 524,288 KV bytes/token, it reports and bills 513 tokens = 268,959,744 bytes. DAG's `pd_host.py` separately records 512-token KV wire bytes (268,435,456) and, with `legacy_prefill_billing_extra_token=true`, adds one token for billing (268,959,744). Its transfer graph records both fields. Both charge 0.007858455882352941 s at the same 255 Gibit/s effective rate in this isolated case. The script audits the original request metrics and graph; `dag-transfer-graph.json` is retained here.

This resolves the arithmetic source of the displayed difference, not the physical model: the independent pipe measurement sends KV plus hidden and controls; the reported KV wire field does not include all these. Its fitted effective bandwidth already absorbs the measured whole transfer and is not a physical link rate. Adding hidden bytes again to that effective fee could double count. This audit does not validate all workloads, eliminate overlaps with compute/CPU/synchronization, or establish the missing consumer first-token cost. Keep original physical and alternative revised-fee outcomes distinct. Both costs remain candidates, with the predictor-adapted baseline; the pristine original and formal validation are not represented here.
