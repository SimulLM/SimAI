# Serial KV installation interval diagnostic

On the two-H800 1P1D service, 512, 1024 and 2048 input-token shapes each ran ten warmup and thirty measured serial requests with eight output tokens. All 120 requests completed successfully and map to one consumer KV-bypass step containing 32 installation calls. The transport hook explicitly synchronizes after each transferred tensor and after all KV installation calls; these samples are intrusive diagnostics, not formal E2E or validation.

For 512, 1024 and 2048 tokens respectively, the median elapsed time from the first installation API start to device synchronization completion was 2.0242, 2.0646 and 2.1450 ms. The sample ranges, p95 values, exact timestamps and warmup labels are preserved. This interval includes host launch overhead, asynchronous device work, other outstanding GPU work and waiting; it is not an isolated non-overlapping KV-installation fee. Time from the last installation API return to synchronization completion is only a bound on then-outstanding work, not total install time. Transport synchronization perturbs scheduling. This single-request experiment does not characterize concurrent batches or establish a common fee contract. Both GPUs were released after shutdown.

The independent SimpleBuffer transfer microbenchmark does not install paged KV. The candidate layer profile and sampler cost have separate boundaries; overlap and accounting must be resolved before adding any installation charge or freezing. Raw client/router/service/worker events and exit status are in raw.tar.gz. No validation completion time was used to tune costs.
