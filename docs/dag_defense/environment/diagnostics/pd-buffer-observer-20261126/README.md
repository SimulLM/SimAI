# Connector host-state observer diagnostic

Two independent real vLLM 0.8.5 1P1D service starts each completed one 512/64 warmup. An opt-in `sitecustomize.py` wraps SimpleBuffer insert and drop-select with host counters and samples its queue and byte count every 0.5 seconds using a nonblocking lock; it does not call CUDA synchronization. The first observer had no cumulative counters, so short calls were not visible. The second recorded one producer insert started/completed and one consumer select started/completed. Four spaced post-response observations matched zero running/waiting/swapped/cache gauges, zero router in-flight requests, zero queue items/bytes and no active observed calls on both worker processes. Observer snapshots were less than 1.5 seconds old; source, request ID, PIDs, counters and samples are in `observer-audit.json`. Services stopped and both GPUs were released.

This is diagnostic instrumentation, not a formal readiness gate. It modifies Python classes and creates a sampling thread; overhead and perturbation are not quantified. A host call returning and an empty Python queue do not prove GPU operations have finished. Sampling can miss transient states; counters cover specific insert/select calls and do not cover every asynchronous device or network operation. Only a successful single request was exercised: concurrent requests, unmatched entries, service crash and timeout cleanup remain unverified. The historical gauge probe returns 2 for connector-unverified; this experiment does not change that behavior. Formal validation remains 0/30.

The archive referenced in `raw-archive-sha256.txt` contains both runs, original service/router logs, gauge samples, observer streams and exit codes. The launcher depends on scripts in the previous `pd-idle-gauge-probe-20261126` checkpoint; its hidden-metric flag differs from earlier calibration and is not part of a frozen configuration. `audit-buffer-observer.py` requires exactly one successful warmup, both observer roles, fresh samples and matching counters; it is specific to this diagnostic and cannot be used as an assertion of general service idleness.
