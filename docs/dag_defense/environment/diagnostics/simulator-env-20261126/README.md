# Simulator environment and synthetic smoke

A separate `/root/autodl-tmp/venvs/simai-simulator` was created with `python3 -m venv --system-site-packages`; it inherits host packages and is therefore not a fully isolated or portable environment. Local packages and pip check are recorded. The existing vLLM environment was not modified. The installation log records the Aliyun PyPI index; `plotly-express` was added after both CLIs initially failed to import it. Both baseline and DAG `vidur.main --help` then exited 0.

Using the existing `scripts/dag_phase6/main.py` fixture with explicitly synthetic profiles, the DAG expanded PD single-request smoke passed its completion, KV gate and cleanup checks. This is a functionality check, not hardware profiling or an accuracy result. The pinned baseline ran the same synthetic request/profile through its own CLI; it exited 0 and produced the request metric, but writing the JSON event trace failed in an atexit callback because a set is not serializable. The original error is retained. A fresh repeat with JSON and Chrome trace flags disabled exited cleanly and saved one request metric; this does not validate the baseline event trace or the real replay pipeline. These tests use fixture model settings and synthetic costs, not the selected model weights or H800 measurements. Full raw directories remain under `/root/autodl-tmp/dag-handoff/runs/simulator-env-20261126/`.

Project profiling documentation points to `microsoft/sarathi-serve` branch `vidur`; the checked-out upstream commit is in sarathi-ref.txt. Its README specifies Python 3.10 and CUDA 12.1, and its requirements pin torch 2.3; it is not installed in the existing vLLM 0.8.5 / torch 2.6 environment. Profiling with Sarathi attention kernels would require verifying whether they match the actual vLLM backend. No hardware profile is claimed here.
