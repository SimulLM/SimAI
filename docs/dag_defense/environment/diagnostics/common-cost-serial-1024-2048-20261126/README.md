For each of two synthetic single-request traces (1024/128, 2048/128), the predictor-adapted baseline with serial first-token modification and DAG use the same independently measured paired consumer receive-to-install-sync and post-sync-to-first-step host medians. Each source length has 10 warmups and 30 measured serial requests; the explicit synchronization perturbs scheduling. The two subintervals are assigned once each, replacing the old transfer and a separate first-token task; the combined interval, KV-install subevents and logits/sampler GPU subintervals must not be charged again. The receive and post-sync median sum is not the same as the median of the combined per-request interval. The fit slope is used only to encode each exact point in the legacy linear interface; do not extrapolate it.

Both implementations completed both cases. Audits verify one Prefill and 127 Decode graphs, one transfer and one consumer first-token task, KVReady <= first-token start/end <= first Decode, equal input fee encoding, no retained KV handles, and equal adapted-baseline/DAG serial request metrics to <1 ns. This closes identified structural duplicate charges for these two serial candidate cases only, not physical wall-clock additivity. Baseline has modified predictor and first-token handling and is not the pristine reference. Producer/output-head scope, CPU/GPU overlap, async transfer, concurrent receive batches, natural batching, router completion tail and shared pristine-original fee mapping remain open; synchronized host time is not proven GPU occupancy.
