# Correlating interrupted validation requests

The candidate collector now sends its existing stable request ID in `X-Experiment-Client-ID`. The candidate router records this ID in the initial monotonic arrival event before contacting either backend. The reconciler can associate raw router events with a timed-out request even when HTTP headers never reached the client, or with a request whose client record is missing after interruption. It retains failure and timeout status; association does not prove backend cancellation or service idleness. Duplicate and conflicting IDs are reported as errors.

The fixture exercises the actual router with local synthetic HTTP backends, including a client timeout before the Prefill response and invalid IDs. The separate collector fixture checks successful requests, HTTP failure, timeout, interrupted client records and router-ID recovery. Both passed; these are software tests, not real inference or validation. Source compilation also passed.
