# First-token counter contract across client and router

The selected router requests vLLM continuous usage counts. Previously it logged `server_first_token` for any first positive count; a final-only count could be mistaken for the first token. The router now records that event only when the first positive count is exactly 1, records the counter with the event, and treats a stream without that observation as an error. The collector already makes the analogous check. Reconciliation now requires counter 1 on both sides for a successful request and retains the client observation. If the first received chunk contains multiple generated tokens, the first-token timestamp is unobservable and the run is incomplete; the collector preserves the raw failure and aborts remaining waves.

Synthetic local router/backend tests cover a valid counter and final-only count 128; collector/reconciliation tests cover missing, duplicate, out-of-order and incorrect token events, failure and timeout. Both scripts exit zero. This is not a hardware or production-service smoke, and old calibration records without the new field must not be re-labelled as conforming to this formal contract. The primary metric remains server arrival to server stream completion; this check improves first-token metrics but does not resolve the simulator last-batch to router-completion residual. Formal validation remains 0/30.
