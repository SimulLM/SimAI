# Follow-up on KV buffer and GPU compute concurrency

Synthetic diagnostic only, not model forward, uninstrumented vLLM service, or formal validation. On two H800 GPUs, vLLM 0.8.5 SimpleBuffer/PyNcclPipe transferred 1024-token FP16 KV (536870912 bytes) and hidden states (8388608 bytes) while GPU0 performed 64 synthetic FP16 4096x4096 GEMMs. For each mode, 10 warmup and 30 measured iterations; logs identify SHM/direct/direct. Actual token IDs and ROI, and sampled key/value/hidden elements, were checked; full KV payload was not checked. Explicit synchronization and fixed mode order perturb timings.

The original token-matching concurrent test hung, as preserved in sibling communication-compute-overlap evidence. A FIFO wildcard lookup with no tokens and no ROI failed because this version requires ROI even when tokens are None; the failed assertion and timeout are retained. Providing ROI completed a short and a full run. In the full FIFO run, compute-only GPU median was 15.784 ms, transfer-only receiver host median 15.764 ms, concurrent two-rank host window median 29.451 ms, and concurrent GPU compute median 29.402 ms. FIFO bypasses production token matching.

A separate test kept actual token matching and waited for the producer match before submitting GEMMs. Three-iteration debug and full 10+30 runs succeeded; the audit confirms all 30 measured match times lay within the producer host interval. Compute-only GPU median was 15.781 ms, transfer-only receiver host median 15.853 ms, concurrent host window median 30.078 ms and concurrent compute GPU median 29.193 ms. Waiting for a match changes ordering and may allow transfer to begin before computation, and host windows do not anchor exact GPU transfer boundaries. These results suggest substantial contention in this controlled setup; they do not prove serialization, identify the original hang cause, validate vLLM production end-to-end overlap, or justify freezing `occupies_gpu` as either true or false. Prior direct torch NCCL microbenchmark gave different overlap, so connector overhead and scheduling matter.

Raw rows, debug logs including the wildcard assertion, thread dumps, source, exit codes and audits are included. Both GPUs were released. Formal validation remains 0/30.
