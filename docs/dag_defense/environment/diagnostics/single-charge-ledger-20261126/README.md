# Single-request fee ledger and freeze conditions

This audit parses all 66 graph files of the existing 512/64 `whole-forward-replay-20261126` sensitivity DAG, not a new GPU run. It asserts one Prefill, one inclusive transfer, one consumer first-token, and 63 Decode graphs. Each Decode graph has one whole-forward task and no layer tasks; Prefill retains 96 layer tasks. It records every task and raw component in `tasks.csv`. The receiver-fit fee (12.557707 ms) replaces the previous effective-bandwidth transfer, not adds to it; the first-token synchronized host interval (0.875779 ms) is one task, not a sum of its GPU and host subintervals; the 63 Decode sampler costs apply to subsequent model steps, not the consumer first-token step. Thus those specifically identified *structural* duplications do not occur in this single-request candidate. This does not establish absence of physical interval overlap, and is not a result for concurrent batches or the untouched original.

The inclusive receiver measurement spans receive, waiting and KV install through explicit sync. The consumer-first-token interval starts after that sync and ends after its own sync. These scopes are disjoint in their instrumented source runs, but sync changes scheduling and the two independently measured quantities do not prove additive production wall time. Whole-forward GPU events exclude KV receive, logits and sampler; the CPU sampler profile includes sampler GPU work and waits and must not also add a separate GPU sampler task. Other CPU/GPU scheduling overlap, final output head/logits, and frontend streaming tail remain unverified. Scope documentation and source pointers are in sibling `completion-fee-boundary-audit-20261126`, `pd-postkv-512-20261126`, `v5-sampler-provenance-audit-20261126` and `last-step-router-boundary-20261126`. The code's original predictor and the adapted predictor are distinct; do not call an adapted baseline untouched.

1. Fix and record the measured mapping of arrival, producer completion, KV-ready, consumer first token, 63 Decode steps for 512/64, and server stream-complete; establish where model completion maps to service completion or separately characterize the residual without double counting. Input/output lengths and EOS rules must agree. Host API return alone is not GPU completion.
2. Provide a shared, versioned computation and communication mapping for all reachable 1024/2048 x 1/2/4 validation batch shapes; document measured scope, interpolation and unsupported cells. The original predictor misses phase/context and RoPE; the whole-forward candidate has incomplete concurrent context coverage. No silent extrapolation or duplicated layer/forward/sampler/receive charges.
3. Complete controlled staggered-two, simultaneous-two and simultaneous-four comparisons after the single-request accounting gate; record first divergence, batch members and costs, and preserve pristine baseline, diagnostic corrected baseline and natural DAG separately. Matched batch agreement applies only to matched keys.
4. Establish an actual pre-run idle procedure showing router, queues, connector, KV cleanup and worker identity; preserve failures and timeouts. Existing sampled gauges and worker-context synchronization are diagnostic, not a fully validated readiness guarantee.
5. Freeze source snapshots, clean/dirty state, all cost files, model and tokenizer hashes, inputs, service settings, arrival/completion clocks, scoring and failure rules with an immutable manifest. Verify each artifact; no validation completion time may set costs. An error near zero is **not** a gate. Report calibrated uncertainty and any known exclusions.

Until the above are evidenced, the ledger status remains open and formal validation remains 0/30. No amount was adjusted against request completion times.
