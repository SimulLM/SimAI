# Fixed groups and shared first-token fees on a real-arrival wave

Replays the same instrumented 2048-input/eight-output four-request wave in `real-first-token-2048-replay-20261126`. Actual arrivals and first-step grouping are reused from that diagnostic capture. The readiness-corrected baseline is additionally modified to delay enqueue for fixed groups [0], [1,2], [3], and to charge each group's inclusive measured post-sync first-token host median once, respectively 1.1103435, 1.115814 and 1.1103435 ms. The existing DAG replay has the same group fees and the original predictor hash; the untouched original remains separately preserved in the preceding diagnostic. Fees and selected wave come from the same instrumented capture and are not an independent holdout. The sample has eight outputs, not the final matrix's 128.

Both versions exit 0, each group is charged exactly once, all member modeled KV arrivals precede the group, and each request starts its seven later Decode steps after its group completes. Each produces 22 model batches, all 22/22 match on stage, request IDs, previous Decode counts and token counts, with matched modeled batch cost difference below 1 ns. Decode positional sequences match; whole-event positional ordering first differs at position 8 due to Prefill vs Decode interleaving. Equal batch membership/cost here does not mean identical timings or all costs: the three group submit times are approximately 114.441, 244.342, 327.396 ms in the fixed baseline and 114.441, 308.678, 427.803 ms in DAG. Their different transfer/resource models affect timing.

This is a fixed-batch diagnostic, not a natural-scheduling or pristine baseline comparison. In particular baseline's group delay does not reserve the Decode GPU against other work, whereas the DAG models GPU demand, so shared resource semantics are not proven; receive, sampler and CPU overlap and stream-completion boundaries remain open. The measured host interval is not pure GPU occupancy. Duplicate group IDs were rejected by an explicit negative test. Original input, model traces and source checks are retained in the preceding archive, while the new baseline commands, process logs, groups and negative test are in the hashed server archive here. No validation completion time informed fees and formal validation remains 0/30.
