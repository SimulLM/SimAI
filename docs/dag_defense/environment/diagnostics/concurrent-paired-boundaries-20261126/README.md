# Paired concurrent receive and first-token host boundaries

Reanalysis of the 560 real dual-H800 1P1D instrumented requests in `pd-kv-ready-bound-20261126/raw.tar.gz`: 1024/2048 input, eight outputs, requested concurrency 1/2/4. Each consumer first-step is keyed by PID and host-step start; all request IDs reconcile exactly to its member set. For each of 402 distinct steps, `steps.jsonl` records receive API start, post-install device-sync return, and first-step sync return on CLOCK_MONOTONIC. The first interval includes receive, wait, install and device synchronization. The second includes post-sync logits, sampling and final sync for the whole batch. Their endpoints are ordered for every step, so they are disjoint in this instrumented host timeline; the combined interval is their union and must not also be charged with either subinterval, KV install, logits or sampler subevents. Repeated steps in one wave are reduced to one median per wave in `summary.csv`; no slow observations are removed.

Measured median receive-to-sync / post-sync by selected group, in ms: 1024 request concurrency 1, actual batch 1: 17.871 / 0.874; concurrency 2, actual batch 2: 35.687 / 0.913; concurrency 4, actual batch 3: 49.900 / 0.704. For 2048 input, concurrency 1 batch 1: 33.488 / 0.690; concurrency 2 batch 1: 73.012 / 0.780; concurrency 4 batch 2: 131.030 / 1.116. For 2048 requested concurrency 4, actual batch 1 has a different 111.225 ms median receive interval; for 1024 requested concurrency 4, actual batch 1 is 129.561 ms, compared to 17.871 ms for requested concurrency 1. Thus `(input length, actual batch)` alone does not identify inclusive waiting and cannot be assigned universally as pure transfer or GPU occupancy. The observed same-wave host receive intervals do not overlap in these 180 measured waves (`wave-overlap.csv`); this is not proof of GPU serialization, and may reflect inserted synchronization. Quantiles are descriptive, from one instrumented session.

The shared post-sync interval is one batch work item, not one item per request. Its durations cannot be added on top of a combined receive-to-first-step charge. A candidate model could split these host intervals once, but mapping them to simulator resource demands and arrival semantics remains unvalidated; requested concurrency is not necessarily observable as a task attribute and the real worker initiates pull within its first model step. The synchronized eight-output diagnostic does not establish production 128-output latency, GPU overlap or async transfer completion. Reject assigning all batched requests their own whole shared fee, or turning these host medians into universal bandwidth. Fixed-batch synthetic comparison established dependency mechanics only; pristine baseline remains separate. No validation completion time informed any cost and formal validation remains 0/30.
