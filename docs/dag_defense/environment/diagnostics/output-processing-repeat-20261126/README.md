# Output processing boundary repeat

In one instrumented 1P1D service session, 10 warmup and 30 measured serial 512/64 requests succeeded. Every request has 64 matched consumer host steps and output-processing intervals, an ID mapping and ordered final choice and router stream completion. The raw archive path and SHA-256 are recorded alongside the audit; full timestamp rows are in audit.json. Both GPUs were released after exit 0.

For 30 measured requests, median (min–max; nearest-rank p95) in ms: final output processing 0.220462 (0.185018–0.577065; 0.467100); processing return to router final choice 0.647002 (0.534959–1.322062; 1.255795); final choice to router completion 0.222172 (0.177594–0.267141; 0.265358). These intervals describe the observed boundary, not separately chargeable costs: CPU profiling may already include work or waits. Host API return does not prove GPU completion. Instrumentation perturbs timing, and this is one service session, not independent production E2E repetitions. The mapping from simulation's last batch end to server stream-complete remains an explicit residual; do not claim equality or add these measurements without a demonstrated non-overlapping scope.
