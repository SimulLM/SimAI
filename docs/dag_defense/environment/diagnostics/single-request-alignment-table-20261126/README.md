# Single-request event comparison, not yet closed

`timeline.csv` records raw timestamps and relative times for three distinct runs sharing the calibration input: original 512/64 streaming calibration router events, an instrumented 512/64 non-stream repeat, and the serial DAG candidate. Each has its own clock origin. The original router completion is its stream-forwarding completion; the diagnostic repeat has explicit GPU synchronization and a non-stream response boundary. Never subtract timestamps between runs or treat the instrumented repeat as original E2E.

One producer prompt step performs sampling and its response reaches the router before the consumer request is sent. A separate token-ID diagnostic found the same first output on both sides for this input. The consumer performs one KV-bypass prompt step and 63 subsequent Decode steps. The candidate DAG explicitly models one consumer first-token step followed by 63 Decode batches. Its first-token task cost is only a synchronized serial sensitivity estimate, not a frozen production fee. The matching adapted-baseline mechanism is separately documented in `baseline-first-token-single-20261126`.

The receive host return is not GPU KVReady. The instrumented repeat brackets serial KV installation with the last install API start and device synchronization completion; the exact GPU completion and actual transport start/end are not observed. The original calibration lacks internal per-request timestamps; queue causes, transfer overlap, completion boundary equivalence and non-overlapping fees remain unresolved. This table makes missing fields explicit and does not claim the single-request gate is closed. Formal validation remains 0/30.
