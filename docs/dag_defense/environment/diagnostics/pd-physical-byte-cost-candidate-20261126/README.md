# Separate revised communication cost and corrected smoke lengths

The independent single-request SimpleBuffer microbenchmark sent FP16 KV and hidden tensors. For this model they contain 524288 and 8192 bytes per input token respectively, excluding token/ROI/control tensors and transport framing. The existing 255 Gibit/s common fee was fitted to elapsed measurements that already include these hidden tensors, using `(tokens + 1) * 524288` as an accounting basis. Adding hidden bytes to that same fee would double count; the shared baseline/DAG comparison fee is unchanged.

`fit_pd_physical_cost_candidate.py` fits a separate affine model to independent microbenchmark times, using KV plus hidden tensor bytes. An even/odd split gives 45 fitting and 45 held-out observations, 15 at each size. Held-out mean absolute errors in milliseconds for the original versus revised split fit are 0.617 versus 0.144 (512), 0.060 versus 0.208 (1024), and 0.347 versus 0.138 (2048). Thus the revised fit does not improve every size. The split comes from the same measurement session, and timing includes matching, producer wait, allocation and synchronization; the intercept is an effective overhead rather than isolated physical latency. Neither fee includes paged KV installation or establishes concurrent service behavior.

The all-sample revised fit is supplied only as `revised-dag-candidate.json` for a separately labelled DAG sensitivity run. To represent KV plus hidden bytes in the current KV-only DAG formula, its bandwidth is converted algebraically for this fixed model; 1024-token simulator transfers were checked against the exact configured latency-plus-bytes formula. `occupies_gpu=true` remains an unvalidated sensitivity assumption. This configuration is not a common-cost comparison with the original baseline, a calibrated service cost, or a parameter freeze.

## Correction to earlier synthetic smokes

The earlier `pd-shape-profile-smoke`, `pd-decode-pull-smoke` and `pd-decode-pull-interleave-smoke` scripts inherited a 576-token trace limit intended for 512/64 calibration. Their nominal 1024/128 requests were actually clipped to 448/128. Their historical outputs remain useful only as functional diagnostics and are retained; they do not test the claimed 1024-token path. The 192 real calibration replays used 512/64 and are unaffected. Scripts now set the limit to 1152 and verify the actual simulator request metrics.

The corrected grouped, interleaved and revised-fee simulator runs were verified post hoc: all simulator processes exited 0, actual requests are 1024/128, each KV payload is 536870912 bytes, and interleaving and revised fee arithmetic pass. Two wrapper checks initially exited 1 because baseline CSV values such as `1024.0` were parsed as integers; the corrected post-hoc audit reads saved successful simulator outputs and the wrapper failures are preserved. Full logs and outputs, including the earlier clipped revised-fee smoke, are in the archive referenced by `raw-archive-sha256.txt`. These are synthetic-arrival functional checks, not real calibration or validation. Formal validation remains 0/30.
