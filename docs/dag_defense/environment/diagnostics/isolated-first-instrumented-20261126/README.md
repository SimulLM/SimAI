# Same-input single-request internal timeline

Repeated the input IDs of the first 512/64 serial calibration request using detailed synchronized instrumentation, after one warmup. The measured request and output lengths, ID mappings, model step events and ordering are checked by `scripts/dag_defense/audit_isolated_instrumented_timeline.py`. Producer executes one prompt step including logits/sampling; consumer executes one prompt-shaped KV-bypass step with logits/sampling, then 63 one-token Decode steps. The diagnostic router consumes the producer response and streams neither that token nor any token to the client; it issues the same prompt to the consumer and returns its non-streaming 64-token response. It does not establish token identity between producer and consumer. The simulator counts one output during producer Prefill and has 63 subsequent Decode steps, so its separately modeled consumer first-token work remains unresolved.

Audit JSON records CLOCK_MONOTONIC raw timestamps for router and model steps. For the measured consumer first step, the last KV installation API began at 1830303371904156 ns and the post-install device synchronization completed at 1830303378857589 ns; GPU KVReady is bounded within that interval, not an exact point. Producer and consumer host timing and CUDA events overlap and must not be added mechanically. This is a new repeated request with explicit synchronization and heavy instrumentation; do not use its time as the original calibration E2E or formal measurement. The previous original streaming router records its `server_complete` after forwarding the backend stream's terminal chunks, not GPU kernel completion. This diagnostic router uses a different non-stream boundary.

The raw archive includes both request responses, logs, event files and exit code. The immediate `gpu-after.csv` was captured while shutdown was still finishing; `gpu-after-settled.csv`, collected after worker processes ended, shows both GPUs released. The diagnostic script's cleanup snapshot should not be used alone as proof of GPU release. Formal validation remains unstarted.
