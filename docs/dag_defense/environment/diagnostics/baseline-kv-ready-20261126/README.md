# Diagnostic fix for premature original-baseline Decode admission

The untouched original scheduler adds a request to the Decode queue at Prefill completion, but only schedules a future wake at `decode_arrived_at`; its queue scan checks that the arrival is finite, not that it is at or before current time. A different event can therefore schedule the request while its modeled transfer is unfinished. In the 32-request concurrent-0 real-arrival calibration replay, 16 requests entered a Decode batch early, by up to 7.579 ms. Request 1 joined the second batch at 48.040 ms even though its modeled Decode arrival was 54.380 ms.

`baseline-diagnostic.patch` changes a separate checkout of pristine commit `cef83f9ddd96540e3e9f48934f11335d52d54fce`: enqueue is postponed to a new event at the already-computed `decode_arrived_at`, followed by the existing Decode scheduling event. Original tracked source remains untouched. This is a **corrected diagnostic baseline**, not pristine original or a final architecture fix. Its transfer formula remains the original non-contending fixed-bandwidth estimate; the actual vLLM pull semantics, shared resource waits, first-token sampling, output boundary and concurrent cases remain unvalidated.

The same concurrent-0 arrivals, original predictor, profiles and 255 Gibit/s fee were replayed; all 32 requests completed and exit code was 0. The exhaustive emitted Decode trace had zero early batch memberships versus 16 in untouched original. Its second batch contains only request 0; request 1 first joins the next batch at 64.961 ms after its modeled arrival. An isolated event test checks premature and duplicate enqueue rejection and wake at the ready time. The DAG also has zero early memberships in this case, but its first `[0,1]` batch starts at 72.820 ms, so additional resource/scheduling differences persist.

Calibration MAE for the same 32 requests is 153.845 ms untouched original, 155.255 ms corrected diagnostic, and 159.134 ms DAG. These are not formal accuracy or mechanism conclusions: boundary compatibility and measurement variability remain unresolved. All violations, timing and task-count detail are in `summary.json`; unmodified results remain in `pristine-real-arrival-20261126`, and full corrected outputs/trace/command/exit reside in `/root/autodl-tmp/dag-handoff/runs/baseline-kv-ready-20261126/`. No validation was used for the change or fitting. Formal validation remains 0/30.
