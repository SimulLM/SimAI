# Calibration replay load and boundary diagnostic

This reuses the 192 real calibration requests and the completed 12 candidate replay outputs; it sends no new inference requests and does not change costs. At each recorded server arrival, `inflight.csv` counts earlier requests whose server-side or simulated completion is strictly later. In the three actual serial repetitions this count is nonzero for 0/32 arrivals; the same fixed-arrival replay produces nonzero counts for 17/32, 31/32 and 19/32 arrivals in both DAG and adapted baseline. In actual requested-concurrency-2 runs, 16/32 arrivals have an earlier request unfinished, versus 21/29/19 for DAG and 20/29/18 for the adapted baseline. This demonstrates a difference in predicted in-flight load under open-loop replay; it does not by itself measure queue length or establish why a prediction differs. Do not alter recorded arrivals to force matching or interpret this as validation.

`segments.csv` separately reports router arrival-to-Prefill response, arrival-to-streamed-usage first token and first-token-to-completion, alongside simulator first Decode start-to-completion. In three real serial repeats, the latter router interval medians are 0.985, 0.855 and 0.818 s; corresponding simulator intervals are 1.025, 1.039 and 1.035 s. The boundaries are not equivalent: router first token is a host streaming observation, while the simulator interval starts before its first modeled Decode step. These descriptive values cannot be added or subtracted as matched CPU/GPU/KV costs and cannot establish an error cause. The variability persists and requires independent resolution before freezing.

Scripts are `scripts/dag_defense/audit_calibration_load_divergence.py` and `scripts/dag_defense/audit_calibration_segments.py`; the input replay archive and checksums are in the sibling `pd-pull-calibration-replay-20261126` checkpoint. Raw real router records are in the earlier independent calibration archives. No validation or accuracy claim; formal validation remains 0/30.
