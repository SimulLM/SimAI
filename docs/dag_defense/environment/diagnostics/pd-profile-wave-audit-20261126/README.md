# PD profile wave audit

The 840 client requests belong to 360 non-overlapping wave windows on CLOCK_MONOTONIC. Model-step events were associated by their start/end timestamp within a unique window, not by request ID; events outside windows, without a shape, or ending after the client wave were excluded. The service logs identify PID 70833 as GPU0 producer and PID 70836 as GPU1 consumer. Producer prefill and consumer decode are reported separately: consumer prefill includes KV receive and is not a transformer prefill cost.

Only 13 of 18 producer-prefill/consumer-decode length/batch points have at least 10 warmup and 30 measured events in this audit. A further 355 events ended after the corresponding client wave and were excluded; this observation requires investigation before assuming a host, GPU and response boundary relationship. See `coverage.csv`, `summary.json` and the mapped events. A wave is not a proven request-to-batch mapping.

Correction to earlier diagnostics: the v8 preliminary profile combined samples from producer and consumer roles and included startup or short-sample events. The earlier v3 and v8 replay comparison also used different effective communication bandwidths (DAG 255 versus baseline 800 Gi-bit/s). Those results are diagnostic only and cannot support same-cost accuracy claims. A corrected replay set both to 255, but source files were edited between the two process launches; its near-identical medians are retained only as a diagnostic and must be repeated from frozen identical code and cost manifests. Skipping CPU overhead was an exploratory sensitivity, not a demonstrated overlap model. Formal validation remains blocked.
