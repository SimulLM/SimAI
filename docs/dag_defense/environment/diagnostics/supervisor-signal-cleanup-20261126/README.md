# Supervisor signal cleanup

The per-run supervisor now catches SIGTERM and SIGINT, records interrupted status, ignores repeated signals while cleaning up, terminates both collector and service process groups, and verifies that both groups are gone. It restores the previous signal handlers afterward. Synthetic process tests cover both signals and the previous service failure/timeout cases; log and exit codes are retained.

A real dual-H800 1P1D service was started by this supervisor with a diagnostic-only permissive gate and a sleeping stand-in collector. SIGTERM was sent to the supervisor itself while collecting. It exited nonzero with `interrupted`, reported both process groups gone, and `nvidia-smi` showed 0 MiB on both GPUs. The service contained no formal requests and this is not a formal readiness test. Its process logs and exact scripts are in the hashed archive on the data disk. SIGKILL, process escape to a separate session, machine crash, and an interruption during service startup are not covered; SIGKILL cannot be handled by the process itself and requires external monitoring. The formal CLI still refuses to start a run because the actual readiness gate is incomplete. Formal validation remains 0/30.
