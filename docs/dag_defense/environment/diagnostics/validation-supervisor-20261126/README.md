# Fail-closed validation supervisor scaffold

`supervise_validation.py` contains a reusable per-run service process-group supervisor. The supervised library path waits for a fresh readiness marker, checks an injected gate, runs at most one collector, detects service death and collector timeout, records status, then terminates the entire service process group even if the leader already exited. It escalates to SIGKILL if needed and refuses to report successful cleanup if the group remains. Each run uses a new output directory and retains status/logs. Synthetic fixture tests cover gate rejection, collection success, nonzero collector, collector timeout and a launcher that exits leaving a same-group child.

The public CLI currently deliberately returns 2 before starting any service: the real fenced admission, connector idle, live worker identity and failure cleanup gate has not been implemented for formal use. The observed conservative metrics probe returns 2 and cannot be promoted to ready. The fixture's permissive gate is test injection, not a production bypass. The CLI is not yet connected to the collector and is not a complete formal runner; it also cannot guarantee termination of a child that deliberately creates a different session or prove GPU state without additional verification. A normal collector exit still requires reconciliation. The failed collector's restart marker and nonzero exit are documented in `collector-failure-exit-20261126`. Formal validation remains 0/30.

`fixture-test.log` records synthetic tests; `gate-status.json` shows the real CLI did not start a service. No GPU was used. The script has not yet been validated against an actual launcher's process tree, pre-response failure, or forced interruption.
