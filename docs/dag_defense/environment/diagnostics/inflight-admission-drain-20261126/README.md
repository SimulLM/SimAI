# Real in-flight admission drain diagnostic

On a real dual-H800 1P1D service, four 512/8 warmups succeeded. During a 2048/128 streaming request, a fence was applied after router arrival while the admission counter showed one active handler. A new request was rejected with HTTP 503. The active request completed successfully with 2048 input and 128 output tokens; the fenced router then reported five accepted, five finished and zero active. Subsequent worker-context CUDA synchronizations bracketed four zero queue/cache observations over 15 seconds; host connector buffers and active calls were zero with stable data/signal counters, and worker PIDs mapped consistently to distinct GPU UUIDs. The existing conservative idle probe returned 2. The service was stopped and both GPUs reported 0 MiB.

This tests one successful in-flight request, not a client cancellation, every backend race or multiple router workers. ASGI completion alone is not evidence of connector cleanup: a prior pre-response cancellation produced a residual item. The host observations are non-atomic and instrumentation affects the service; the formal collector's live gate is not integrated and validation remains 0/30. Raw client, worker, router, sync, service and process evidence is in the hashed data-disk archive.
