# Real service idle-gauge probe

Two independent real vLLM 0.8.5 eager FP16 TP1 1P1D diagnostic starts each executed one successful 512/64 warmup request, then sampled router state and both `/metrics` endpoints four times five seconds apart. Default startup exposed zero running, waiting and GPU-cache gauges but omitted swapped-request and CPU-cache gauges. The second start added `--show-hidden-metrics-for-version 0.7`; all five gauges were visible and zero on both roles in all four samples, and the router recorded no unresolved requests/errors. Both services stopped and both GPUs showed zero allocated memory afterward. Outputs, request IDs, launch scripts, raw server/router logs, and observations are retained in the referenced archive.

The metrics endpoint cannot expose SimpleBuffer's pending queue and can report stale sampled state; zero values and a completed router response cannot establish connector empty or guarantee that a timed-out backend stopped. The hidden-metrics option changes startup arguments relative to the earlier calibration and is not silently adopted as a frozen service configuration. These observations are diagnostics, not proof of post-warmup KV cleanup, service identity or formal readiness.

The first probe version returned exit 0 on `gauges_zero_connector_unverified`; the historical script and output are retained. The current `scripts/dag_defense/probe_pd_idle.py` instead returns 2 for both zero-but-unverified and missing metrics, and 1 for observed activity/error; it cannot produce a successful readiness exit while connector state is unverified. An offline endpoint test and synthetic zero/missing/busy fixtures confirm this behavior. A proper connector-state check and full run orchestration remain necessary. Formal validation is 0/30.
