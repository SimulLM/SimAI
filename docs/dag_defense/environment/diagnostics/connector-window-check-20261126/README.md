# Host connector observation window checker

The checker joins stored Prometheus/router observations with fresh same-role connector snapshots and verifies an observation window of at least 15 seconds, monotonic timestamps, unique worker roles, zero queue/pipe host state, balanced data-pipe calls, and the expected number of completed insert/select calls. It was run against the preceding four-concurrent-request diagnostic: host observations were consistent across a 15.09-second window. Its CLI deliberately returns status code 2 even on consistent host observations because GPU completion, live process ownership and full connector readiness remain unverified; failures also return 2 with a distinct incomplete status and reason.

A test reuses the archived real observations and verifies rejection of busy router state, incorrect request count, stale snapshots and missing producer observer. The checker does not run the formal experiment, establish safety after timeouts or crashes, or authorize validation. It reads saved observations and does not query current live process identities. Run with Python without optimization, because its assertions enforce checks; optimized execution is explicitly rejected.
