A separate single-H800 offline vLLM 0.8.5 eager FP16 TP1 diagnostic measured 2048-input batch 2 and 1024-input batch 3, 128 outputs, 10 warmup and 30 measured waves each. All 200 requests succeeded. The sixteen 16-token context bins independently met 10/30 uniform-context wave coverage; wave medians and all source hashes are retained. The process exited 0 with a documented NCCL process-group cleanup warning and both GPUs then showed 0 MiB. Detailed GPU synchronization can perturb timings; this is single-GPU full forward, not real 1P1D E2E, and excludes KV, CPU, logits, sampler and router.

`merge.py` adds the qualified non-duplicate points to the previous candidate. Previously qualified points remain selected on duplicate keys; sources and decisions are in `merge-audit.json`. This is not a freeze. Replay of a synthetic 2048/128 simultaneous four-request trace with the adapted baseline and DAG uses the candidate for covered shapes. DAG completed 130 forward batches; adapted baseline stopped after 11 forward batches at contexts [2058,2058,2049,2049], span 9, which the <=1 span coverage guard correctly rejects. The three batch keys matched before failure have equal forward costs: 3/11 observed adapted-baseline batches and 3/130 DAG batches; no comparison is possible for missing baseline output. Concurrent first-token fee was intentionally omitted, so this is not an E2E fee model. Original pristine source remains unchanged, no validation was run and no conclusion extends to all shapes.
