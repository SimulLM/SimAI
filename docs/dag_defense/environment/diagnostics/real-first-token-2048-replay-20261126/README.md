# Real-arrival 2048 first-token replay and pristine reference

One measured 2048-input/eight-output requested-concurrency-four wave from the synchronized 1P1D diagnostic supplies actual router arrivals. Original SimAI at pristine cef83f9 was replayed separately; DAG uses the original predictor plus opt-in batched first-token tasks. Actual and DAG first-token groups are [0], [1,2], [3] (3/3 on each side). Each modeled KVReady precedes its shared task and each task completes before member Decode; each request has seven subsequent Decode steps and releases KV.

The original forms 21 total Prefill/Decode batches, DAG 22; 20 batch keys match, with task cost agreement below 1 ns for those matched compute batches only. Original has six early Decode memberships against its modeled per-request decode_arrived_at (largest 29.992 ms); DAG has none. The first positional Decode membership difference is the seventh Decode batch, original [0,1,2] versus DAG [0]. This is not a claim that the real system behaves like either simulator. The original has no equivalent consumer first-token task, so this is not a complete same-fee comparison; original results must not be conflated with the modified fixed-batch baseline. The 3/3 first-token pairing is specific to this instrumented wave.

First-token candidate medians are batch-1 1.1103435 ms and batch-2 1.115814 ms from 10 warmup/30 measured waves of the same synchronized capture, including this wave. They are inclusive post-KV-sync host intervals; subintervals must not be added. Treating them as GPU occupancy is unproven. The data are not an independent holdout; the capture has eight outputs and a nonstreaming router, and does not freeze transfer/compute/CPU or completion boundary. Original and DAG use the same underlying predictor and transfer configuration, but actual total costs and first-token stage differ. No validation completion times set fees; formal validation remains 0/30.

Raw commands, both traces, logs, first-token events and exit codes are in the hashed data-disk archive. `audit.py` verifies events and membership against the retained original source run.
