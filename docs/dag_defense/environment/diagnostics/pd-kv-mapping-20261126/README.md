# Concurrent KV token association diagnostic

Four distinct 2048-token prompts were submitted as a Prefill wave followed by a Decode wave using the real vLLM PyNccl connector, eager mode and 8 GiB buffer. All eight backend calls succeeded. A synchronizing diagnostic hook computed SHA-256 over each input token tensor at producer insertion and at consumer lookup, and over the returned token tensor. For each client input index, the verifier matched the hash to the Prefill batch containing its backend request ID and the Decode batch containing its backend request ID, verified exact query/returned token hashes, confirmed per-item key/value/hidden byte counts and checked that GPU-synchronized KVReady with bypass followed lookup. Each of the four associations passed; see `mapping-verification.json` and raw events.

The hashes cover token IDs, not every KV or hidden-state byte. Association of those tensors with the matching token item follows the inspected SimpleBuffer bundled-item implementation; sampled tensor-content verification remains separate. The diagnostic uses CPU copies and CUDA synchronization and is not a performance or production E2E trace. The producer and consumer IDs differ and are paired by the client input index. SimpleBuffer performs prefix matching, so unique equal-length prompts are required for this test; this does not prove correctness for arbitrary shared-prefix or mixed-length workloads. The servers were intentionally stopped (exit 143).
