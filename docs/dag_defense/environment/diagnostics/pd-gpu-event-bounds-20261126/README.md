# Real PD forward and NCCL CUDA-event timing bounds

Separate profiler diagnostic, not uninstrumented E2E or a frozen fee. vLLM 0.8.5 eager FP16 TP1 real 1P1D; request lengths 1024 and 2048, output 8 tokens, requested concurrency 4; 10 warmup and 30 measured waves per length. All 320 requests succeeded with expected token counts and the router mapped Prefill and Decode IDs. Source GPU model forward and large PyNccl send calls were bracketed by CUDA events on their streams. A background thread polls event readiness without device-wide synchronization and records last-known-incomplete and first-known-complete times on the shared CLOCK_MONOTONIC. Hooks, inserted events, polling, and the diagnostic router can perturb execution. CUDA-event intervals may encompass host launch gaps and stream waits; they do not prove individual GPU kernels execute simultaneously.

A strict positive overlap lower bound requires both starts' latest possible times to precede both ends' earliest possible times. Of 30 measured 1024-token waves, one had an overlap lower bound of 6.67554 ms between source model-forward and a 268435456-byte NCCL send event interval. Of 30 measured 2048-token waves none satisfied the strict test; this does not prove absence of overlap because event bounds can be wide. NCCL sends lack request IDs and are associated by non-overlapping client wave windows, not by individual request; the audit verifies no window overlap, all request ID mappings, producer process identity, and at least eight large sends in each measured wave. The exact positive pair is in overlap-proofs.json. This establishes a bounded event-interval observation in this diagnostic, not a measured fraction of GPU exclusive time or a completed compatibility contract. 8-token output and buffering differ from the formal 128-token streaming workload.

The first version failed because a diagnostic wrapper changed the vLLM keyword argument name; error and source are retained. The first corrected version passed its smoke but polled starts only after end events were submitted and gave overly wide start bounds. The final version begins polling immediately. An interim audit edit had a syntax error and was corrected without changing measured data. All logs, errors, timing records, code and checksums are preserved. Both GPUs released; formal validation remains 0/30.
