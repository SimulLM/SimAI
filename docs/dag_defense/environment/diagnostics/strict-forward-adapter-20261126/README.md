# Measured-forward adapter diagnostics

On CPU, the opt-in runtime adapter replays independently measured full-forward candidate values in an adapted diagnostic baseline and DAG. For 1024/128 single, 2048/128 single, and 1024/128 simultaneous two, each side completed 1 Prefill plus 127 Decode batches. All 128 corresponding batches per case had matching IDs, contexts, lookup keys and full-forward costs; every DAG graph had exactly one forward task and no layer tasks. This only covers these cases and this cost component, not all computation, communication, total timing or the unmodified original. The adapter rejects unmeasured shapes and is not a frozen model.

In 1024/128 simultaneous four, both adapted baseline and DAG failed at the same unmeasured uniform-context batch-4 bin 1040. The incomplete outputs and first exploratory two-request failure caused by a single-request first-token guard are retained. The later concurrent-only diagnostic sets that first-token fee to zero; this is an explicit omitted cost, not an accepted physical value. The transfer and other costs in the two configurations are not established as common physical fees. No E2E or validation data were used to set forward costs.

`audit.py` checks the final four run directories and 128 DAG task graphs in each successful case; `test.log` covers strict lookup and rejection of invalid or missing shapes. The complete run logs, command files, traces, exit codes, diagnostic config, and prior failed attempts are in the hashed archive on the server. Replay uses `run.py` and `trace.csv` as an example with the paths encoded in the script; the other exact commands are retained in raw runs. No GPU was used for these replays. Formal validation remains 0/30.
