# Isolated same-fee receiver sensitivity

The independent synchronized serial receiver fit replaces, rather than supplements, the old 255 Gibit/s transfer task for the same 512/64 calibration input. Diagnostic DAG and predictor-adapted baseline both use 0.012557707323809522 s for the complete receive-plus-install candidate and 0.000875779 s for the distinct post-KV first-token candidate. Auditing confirms one transfer task, one consumer first-token task, 63 later Decode batches, same input/output counts and equal simulated E2E (1.0581126611955285 s versus 1.058112661195563 s). It does not add the old transfer fee or a separate installation fee.

This is a single-request implementation and accounting sensitivity, not a physical accuracy or improvement conclusion. The receiver fit was derived from a synchronized diagnostic and contains transport, matching, waiting and installation; CPU/GPU overlap, request boundary differences and concurrent batches remain unverified. Baseline modifications (including the earlier first-token diagnostic) are preserved as a patch on top of the predictor-adapted original; pristine original remains separate. A real CLI check confirms the baseline receiver override rejects a 32-request trace even without the first-token option. Full individual run output remains in dag-handoff/runs; no validation data or completion times were used to choose the fee. No parameters are frozen.
