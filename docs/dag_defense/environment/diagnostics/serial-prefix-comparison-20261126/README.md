# Real serial prefix event ordering

This joins the existing 20 measured requests from `light-serial-512-20261126` by router ID, prefill backend ID and decode backend ID. For each request it asserts the actual host event ordering and uses the request's router arrival as time zero. The events are host observations, not exact GPU start/end or GPU KVReady. All requests share a single session, input and instrumented service; they are not independent sessions or formal validation.

Median relative host times: producer worker start 3.238 ms, producer connector send API start 15.380 ms and return 16.745 ms, producer worker return 26.831 ms, router prefill response 28.197 ms, Decode worker start 31.179 ms, receive API start 31.283 ms and return 34.335 ms, first consumer step return 41.659 ms and router first-token observation 42.416 ms. Exact per-request records and full ranges are in `requests.csv` and `summary.json`; source raw events remain in `light-serial-512-20261126-raw.tar.gz`.

The `receive-sensitivity-single-20261126` DAG candidate has modeled Prefill completion and transfer start both at 23.397 ms, modeled KVReady at 35.955 ms and first consumer task end at 36.830 ms. These simulated and real events have different scopes, and cannot be equated or subtracted as a pure cost error. In particular the producer send API precedes its worker return and Decode worker begins before the receive call; neither host send nor receive return proves GPU transfer completion. This demonstrates a concrete sequencing distinction and missing separately identified route/dispatch intervals, not an independently measured router fee. Do not use these times to fit or freeze fees; account for existing CPU and sampler overlap before making changes.
