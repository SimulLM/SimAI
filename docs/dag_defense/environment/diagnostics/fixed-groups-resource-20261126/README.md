# Fixed-group decode slot occupancy sensitivity

CPU-only diagnostic on the same instrumented 2048/8 four-request arrival sequence, fixed groups and first-token fees as `fixed-groups-real-fee-20261126`. The previous modified baseline started group [3]'s 1.1103435 ms first-token interval while an existing [1,2] Decode batch was running; all 1.1103435 ms overlapped. DAG had no such overlap. The new opt-in modified baseline instead waits until its decode scheduler is free, occupies one decode scheduling slot for the group's first-token interval, releases it, then enqueues its members. It is not the unmodified original or a natural scheduling implementation. It assumes exclusive slot occupancy, not established real GPU exclusivity; whole-batch slots and DAG's task demands need not mean the same physical thing.

Audit confirms no first-token/Decode batch overlap on this trace, all three measured group fees once each, modeled KV arrival before group execution, seven later Decode steps per request, and 22/22 matched model batch keys with identical cost within 1 ns against the prior DAG run. Decode positional sequence matches. The first whole-event positional difference is a Prefill/Decode interleaving, not a membership mismatch. Baseline group [3] starts at 332.079 ms instead of 327.396 ms and requests 1, 2 and 3 finish 1.1103435 ms later than the non-reserving fixed baseline. The corresponding DAG group starts at 427.803 ms; its different transfers/resource scheduling remain unresolved. These values are sensitivity results, not measured production delays or an accuracy score.

Both fixed baselines are altered diagnostic variants, group identity is taken from the same instrumented real wave, measured fee and wave are not a holdout, and workload is eight output tokens. The untouched original is separately preserved in `real-first-token-2048-replay-20261126`. Neither this single case nor excluding this modeled overlap proves all cost assignment, natural scheduling, physical GPU overlap or router boundary. No formal validation occurred. Audit and original traces are referenced in the hashed archive; no requests used validation completion time for fee fitting.
