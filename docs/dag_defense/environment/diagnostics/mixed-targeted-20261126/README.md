Two cases each ran 10 warmup and 30 measured distinct waves, with 128 outputs, greedy sampling and ignored EOS: 1024 input batch 2 with exact relative context [0,1], and 2048 input batch 4 with [0,0,8,8]. All 240 requests returned the requested length. Each case has eight rounded 16-token context bins with 10/30 wave coverage. The audit retains every wave including outliers; no slow samples were discarded. Process exit 0, process log contains an NCCL process group cleanup warning, and both GPUs returned to 0 MiB. The event hooks synchronize each step and can perturb timing. These are offline single-GPU model-forward GPU-event intervals, not real PD E2E and do not include KV, CPU, sampling, logits or router costs. Same-session waves are not independent service restarts.

`coverage.csv`, `wave-samples.csv`, `audit.json` and hashed raw archive preserve samples, exact commands, logs, request IDs and per-event timestamps. An extended candidate lookup was built from prior qualified tables and these exact measurements; no missing pattern was filled by assuming another equivalent. The synthetic 2048/128 four-request adapted baseline and DAG replay each exited 0 with 138 and 130 forward batches respectively. Four batches match on phase, request IDs, per-request contexts and lookup key: 4/138 baseline and 4/130 DAG, with identical forward costs for those four only.
