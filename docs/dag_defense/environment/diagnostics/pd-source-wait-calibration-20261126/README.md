# Source-wait candidate: independent calibration replay

The six previously collected independent 512-input/64-output real 1P1D calibration repetitions (192 measured requests) were replayed from actual router arrival times using the opt-in source-batch-wait DAG candidate and the independently measured 5.5387335 ms 512-token host dispatch interval. This interval was measured with synchronization, serial concurrency and eight output tokens; its use here is a sensitivity hypothesis, not a proven 64-token or concurrent service fee. All six new DAG simulations exited 0; their active source-wait and dispatch config, request length and count were verified. The adapted baseline results were reused from the earlier replay; input traces, request maps, baseline outputs and profile content were checked by hash. Original real data and previous replay remain unchanged.

`comparison.json` retains six per-case mean absolute errors against router E2E. The source-wait candidate versus prior DAG changes, in milliseconds, were: concurrent 0: 169.32 to 164.64; concurrent 1: 347.92 to 362.29; concurrent 2: 273.69 to 265.49; serial 0: 271.10 to 271.45; serial 1: 182.32 to 187.86; serial 2: 272.58 to 273.96. Thus the candidate improves two cases and regresses four on this calibration, with no consistent improvement demonstrated. Router and simulator boundaries are not yet proven identical; real timings vary across repetitions. These are calibration diagnostics, not validation, and do not justify a final accuracy ranking or a freeze.

Both variants use identical compute, attention, CPU and network profile contents and explicit 255 Gibit/s baseline/DAG communication parameter. All 24 generated prediction CSVs per case match by logical prediction name and file hash. The first verification attempt compared cache filenames literally and failed because the filenames include a path-derived hash; after matching unique logical names, all content hashes passed. No predictor values were modified. Matched-batch audit compared 7948 batch histories: all corresponding DAG task-cost sums and adapted-baseline batch durations agree within 1 ns. Unmatched batches, differences in event timing/resource waits and the adapted versus pristine baseline caveat remain. The new dispatch/source-wait behavior changes scheduling and adds time in the DAG sensitivity, so it is not itself a symmetric common-fee change.

`requests.csv`, `summary.json`, `comparison.json`, `common-cost.json`, `batch-summary.json` and compressed per-batch rows preserve results. The referenced archive includes six DAG runs, reused baseline outputs, profiles, commands, request maps, logs and audits; reconstructible pickle caches/lock files are excluded. The earlier real data, delay diagnostic, common-fee replay and untouched original are retained separately. Cost overlap, service scheduling, idle and first-token boundaries remain unresolved. Formal validation is 0/30; no freeze exists.
