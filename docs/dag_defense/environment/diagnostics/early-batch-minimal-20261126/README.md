# Two-request premature batching reproduction and wake test

Two requests use the first two measured router arrivals of independent 512/64 concurrency-2 calibration (0 and 0.481173 ms). Three CPU simulator executions use the same trace, original predictor, profiles and 255 Gibit/s transfer fee: untouched original; original with only the modeled KV-ready admission timing changed (`baseline-diagnostic.patch`); and DAG with the same original predictor. DAG retains its distinct resource and pull scheduling and is not a fixed-batch control. All three exited 0 and completed two requests. This is a minimal replay of real arrival timestamps, not a new real inference or formal validation.

Untouched original schedules request 1 in its second Decode batch at 48.040 ms before that request's modeled 54.380 ms Decode arrival. In the corrected baseline and DAG, second Decode batch contains only request 0. Both next batches contain requests 0 and 1: corrected baseline starts at 64.961 ms, DAG at 72.820 ms; equal membership does not imply identical timing. The original has one premature membership in this two-request example; corrected baseline and DAG have zero. The event unit test checks rejection before the ready time, enqueue and worker wake exactly at the ready time, and rejection of duplicate enqueue. The corrected baseline remains separately labelled and its underlying fixed-bandwidth transfer cannot establish real GPU KVReady.

Matching uses replica, request IDs, each request's previous Decode count and per-request token counts, including Prefill and Decode stages. Original vs DAG: 4/67 DAG batches and 4/66 original batches matched (5.97% and 6.06%). Corrected vs DAG: 67/67 on both sides matched (100%) **only for this two-request trace**. For each matched batch, summed DAG task costs excluding resource wait match the corresponding original or corrected batch execution cost within 1 ns. This is not proof of equality for unmatched shapes or other workloads. The previously observed 32-request replay had many unmatched batches; do not generalize this minimal result. All three full logs, commands, traces and exit codes are preserved in the archive named by `raw-archive-sha256.txt` on the data disk. Timing and fee compatibility remain open; no error target is a validation prerequisite.
