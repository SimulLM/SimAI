# Model boundary operation diagnostics

This repeat of the eager vLLM FP16 TP1 CUDA-event profile added hooks around the actual model's embedding, final normalization and logits processor, in addition to the middle-layer hooks. The GPU0 server and model, CUDA event method, synchronization after each step, lack of prefix/chunked prefill and logging limitations are the same as the preceding compute profile. The diagnostic client issued 987 synthetic two-output-token requests, all completed and mapped to one prefill and one decode step; an initial six-token smoke contributed two intentionally unmapped steps. All 17 requested phase/input/actual-batch shapes have at least ten prior shape warmups and 30 eligible samples. Under the 4096 batched-token limit, 2048-token prefill waves of four split.

Embedding and final normalization are timed only when the full model forward runs; a real PD consumer receiving hidden states skips that forward on its first output step, while the logits processor still runs. The logits processor interval may include stream idle or host-launch gaps. These are diagnostics, not E2E times and not yet a common cost model. In particular, output head and embedding are per-step costs, not per-transformer-layer costs. The simulator currently lacks equivalent explicit fields; faithful mapping and overlap with host sampling need validation before calibration. The server exited 143 because it was intentionally stopped. Raw events, client requests and server output are compressed; SHA256SUMS preserves the packaged bytes.
