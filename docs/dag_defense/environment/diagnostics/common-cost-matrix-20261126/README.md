# Common-cost matrix: adapted baseline and DAG

Synthetic mechanics diagnostic; this is not real inference, calibrated cost, parameter freeze, or formal validation. Used candidate v5 profile, adapted original scheduler and DAG predictor, 1P1D TP1, 128 output and requested simultaneous waves at 1024/2048 input x 1/2/4 requests. A first attempt failed at 2048/2 because the prefill attention lookup grid was restricted to 2048; the predictor queries sqrt(sum(prefill_length^2)), which exceeds 2048 for two requests. Original failed logs and exit codes are preserved. The second attempt increased the query grid to 4096, kept the scheduler limit at 4096 tokens, and completed all 12 runs. Trace audit verifies every prefill batch stayed <=4096 tokens; 2048/4 split into two 4096-token batches in both versions. Expanding the grid is not proof of profile coverage or prediction accuracy.

All 17 training prediction CSV hashes match for each paired run. Matched batch keys include replica, request IDs, previous per-request decode counts, and token counts. Matched batches in these cases were 128,1,1,128,1,10 respectively; remaining batches did not match due to different scheduling. The summed DAG task cost matched corresponding baseline batch total within 1 ns in all matched cases. In the 2048/4 case, one matched prefill batch had 61.024 ms additional DAG timeline duration: its first attention task waited for a resource while the configured KV transfers occupied both GPU resources. This is modeled contention under `occupies_gpu=true`, not proof of exclusive GPU occupancy in real NCCL transport. The audit is specific to matching batch histories and cannot prove cost equality for unmatched or mixed-length batches. Preserve adapted baseline as such; untouched original is separately archived. These synthetic results do not prove timing-boundary compatibility; formal validation remains 0/30.
