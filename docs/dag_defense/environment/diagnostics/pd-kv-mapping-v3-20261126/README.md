# Concurrent KV sampled-content diagnostic

Four unique equal-length 2048-token inputs passed through the real GPU0 Prefill and GPU1 Decode PyNccl connector, with eight successful backend calls and a GPU-synchronized KVReady for every Decode ID. The diagnostic maps client index to Prefill and Decode backend IDs and compares SHA-256 hashes of the producer token IDs, consumer lookup token IDs and returned token IDs. For each item it also hashes selected K and V slices `[:, :3, :1, :8]` and hidden-state slice `[:3, :8]` at insertion and after receipt. All corresponding source/target hashes matched; the four inputs produced four distinct hashes for each sampled K, V and hidden field. The raw events and verifier show the mapping and timing order.

These are sampled slices, not full-tensor integrity hashes. The hooks copy data to CPU and synchronize GPUs, so this run cannot be used for performance measurements. Matching unique equal-length prompts exercises the workload shape but does not establish correctness for arbitrary mixed-length or shared-prefix workloads; SimpleBuffer uses prefix matching. Production request/batch event capture and low-overhead timing remain separate requirements. The server exit 143 was an intentional stop. The first verifier's output is preserved as `mapping-verification-v1.json`; the later report adds explicit sample hashes and uniqueness checks, while the raw events remain unchanged.
