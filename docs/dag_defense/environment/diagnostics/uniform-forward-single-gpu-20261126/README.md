# Uniform batch-four forward microbenchmark

An independent single-H800 offline vLLM 0.8.5 eager FP16 TP1 model-forward benchmark used fixed 1024/2048 input and 128 output, four requests per wave, 10 warmup and 30 measured waves for each length. All 320 requests completed at the requested lengths. CUDA events, explicit per-step synchronization, full request IDs and wave timestamps were recorded. Each of the sixteen uniform-context batch-4 bins contains 10 warmup and 30 measured distinct waves. `coverage.csv` and `wave-samples.csv` retain medians, ranges, p95 and individual wave medians. Both GPUs returned to 0 MiB. Exit was zero; process log reports NCCL process-group cleanup warning at exit.

This is isolated single-GPU compute measurement, not dual-GPU PD E2E; GPU event hooks and synchronization perturb timing. Forward excludes logits, sampler, KV transport, CPU and router, and replaces layer compute rather than being added. Compared descriptively with earlier PD mixed-context batch-4 runs, medians differ by -2.3% to +2.5%; these are different sessions and compositions, not a causal equivalence test or universal bound. The candidate file explicitly labels the new points `single_gpu_uniform_diagnostic`, retains separate mixed points and never fills other missing shapes. No result is frozen.

On a synthetic simultaneous 1024/128 four-request trace the adapted baseline and DAG each completed 128 batches, with 128/128 matched forward keys and costs and one whole-forward task per DAG graph. In the 2048/128 four-request trace, original attention lookup grid 2048 failed; increasing it to 4096 allowed Prefill splitting but both replays then failed closed at missing uniform Decode batch-2 bin 2064. Concurrent first-token fee is omitted in this diagnostic; other cost and timing boundaries remain open. Neither adapted baseline nor isolated compute is the pristine original or formal validation. The full raw event data, failed attempts, commands and logs are in the hashed server archive. Formal validation remains 0/30.
