# Adapted baseline and DAG cost smoke

One synthetic 512/64 request was replayed by the original scheduler with the recorded predictor adapter and by the DAG checkout, using the same candidate profile. This is a mechanics smoke, not formal validation or an independently calibrated/frozen cost set. Both processes exited 0. The predictor source hashes match, and each of the 17 generated training-prediction CSV hashes matches. Per-request model execution time and billed PD transfer time agree within 1e-12 seconds, and transfer bandwidth is 34225520640 bytes/s on both. DAG exposes 268435456 wire bytes while baseline exposes 268959744 billed bytes; DAG legacy plus-one billing yields the same time. Full outputs, commands, predictor hashes and verification are preserved.

This demonstrates equality for one request only; it does not verify every runtime cost or concurrent batch shape. The v5 profile is a candidate with known source/mode and overlapping-accounting limitations, and this smoke does not establish alignment to real H800 or KV pull scheduling. Adapted original scheduler is not identical to fully unmodified SimAI; the adapter diff and pristine smoke are preserved in the sibling pristine-baseline-smoke directory. A comparison against untouched original must remain separately labelled. Both versions used the historical TP network-device label a100_pairwise_nvlink; TP1 and explicit PD bandwidth mean this is not evidence of NVLink. Formal validation remains 0/30.
