# Dynamic readiness-corrected baseline and DAG first-token groups

Opt-in CPU diagnostic on the same 2048/128 synthetic arrivals as `controlled-2048-three-way-20261126`: one, two staggered, two simultaneous, four simultaneous. The diagnostic baseline uses the readiness-only corrected original scheduler plus a dynamic first-token group selector instead of fixed request IDs. On a free Decode slot, it chooses the oldest ready requests subject to configured batch and token limits, charges the common candidate measured first-token fee once, reserves the slot, and releases members after completion. Unmeasured shapes fail. This is modified baseline code, not untouched original or a validated replica of vLLM scheduling. In particular its priority over existing Decode queue entries and its whole-batch slot approximation differ from the DAG; a single-case match does not prove general equivalence.

The first attempt failed in all four cases because CSV input length 2048.0 was used as a string fee key; the code now validates integral lengths and uses integer keys. Both failed and corrected runs are preserved. Four corrected runs exit 0. For each scenario dynamic baseline and existing DAG form identical first-token group membership and per-shape fees: [0]; [0],[1]; [0,1]; [0,1],[2,3]. Model batch matches are respectively 128/128, 134/134, 128/128 and 137/137 on both sides, with costs for paired model batches within 1 ns. Every request has 127 later Decode steps, no modeled early admission, and dynamic first-token tasks do not overlap a Decode batch in that trace. Group start times and overall delays can still differ; identical membership is not identical real timing.

Pristine original remains separately compared in `controlled-2048-three-way-20261126` and lacks the consumer first-token stage. This result uses synthetic arrivals, post-KV host medians from an instrumented 8-output profile, and model resource assumptions; it does not prove 32-request natural batching, physical GPU/transfer overlap or same total physical fees, nor close the formal gates. Audit uses separate source paths and preserves early membership, first differences, per-group fees and counts. Original logs and failed attempt are in the hashed archive. No formal validation and no E2E-derived fee fitting occurred.
