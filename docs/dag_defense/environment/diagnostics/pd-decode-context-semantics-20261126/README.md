# Decode context semantics: single request

The audit joins consumer GPU model-step request IDs from the independently captured 1024/2048 input, 128-output real PD diagnostic to client records. For each of 80 unambiguous requested-batch-1 requests (including warmups), the 127 actual decode forward steps had sequence lengths exactly input+1 through input+127. The script also constructs simulator Request objects and executes their actual prefill/decode transition methods: for both input lengths the simulator's 127 post-prefill `num_processed_tokens` values are exactly the same and the request completes. The predictor's decode attention input is integer mean of these processed counts rounded up to 16-token blocks. Source file SHA256s are in audit.json. The first exploratory simulator call omitted required on_batch_schedule and raised an error; the corrected audit uses the public lifecycle properly.

This verifies numerical context alignment for single requests only. It does not establish mixed-batch equivalence, first-token execution location, KVReady, routing, CPU/GPU overlap, or an independent complete cost model. The real data used synchronized detailed profiling, not formal E2E. The earlier context-bin table contains whole forward events and is not an attention-only fee. Formal validation remains 0/30.
