# GPU compute and communication microbenchmark

Independent synthetic diagnostics on the two H800s, not model inference, vLLM end-to-end, formal validation, or a new calibrated cost. A direct `torch.distributed` NCCL point-to-point test used one 545259520-byte FP16 tensor, GPU0 synthetic 64 x 4096x4096 FP16 GEMM on another stream, 10 warmup and 30 measured iterations per mode. NCCL logs show SHM/direct/direct. Each received tensor was checked only at its first and last elements. Both ranks completed all 120 iterations; GPU memory returned to zero.

Median GPU0 host durations were 15.520 ms for compute only, 14.740 ms for transfer only and 18.216 ms for concurrent. GPU0 GEMM CUDA-event medians were 15.488 ms alone and 18.145 ms concurrent. The median host interval from the earlier rank start to later rank end during concurrent iterations was 18.216 ms. This indicates partial overlap under this synthetic direct-NCCL setup, but host windows do not anchor exact GPU communication start/end. It does not establish the overlap factor or exclusivity for vLLM PyNccl SimpleBuffer, its metadata transfers, actual transformer prefill, or real workloads. Fixed mode order and explicit synchronization also perturb execution.

An attempted vLLM SimpleBuffer plus GEMM microbenchmark stalled in its first concurrent iteration after completing isolated modes. It was stopped; two short follow-up debug runs also timed out, including one with extra synchronization before token matching. Thread dumps show producer-side matching waiting while the consumer waited on receive, but the underlying cause is not established. Debug synchronization itself changes behavior. Preserve all three failures and do not infer that actual PD or hardware lacks concurrency; previous actual PD requests succeeded. Initial audit also failed due to a string/integer rank mismatch and was corrected without changing measured rows; record retained.

These results challenge an assumption of universal GPU exclusivity, but cannot select `occupies_gpu` for the real service. Resolve or bound actual connector scheduling and cost overlap before freezing. Raw logs, row data, failures, thread dumps, scripts and SHA256SUMS accompany this document. Formal validation remains 0/30.
