## 2. 维护与完成口径

- Issue/PR 记录开发细节；本表仅汇总验收证据及结论，不另设一套任务状态。任务流程为待开始、开发中、待评审、待验收、完成；本表结论为未验收、待补证、通过、未通过。
- 每项验收引用任务/PR、实际提交、输入/config 哈希、命令、退出码、测试结果、运行编号、归档获取位置、审核人及日期。无证据不通过；本地路径不是团队可获取位置。
- 实验说明保存至 `docs/plan/week2/records/`，编号为 `W2-M<成员编号>-YYYYMMDD-<序号>`；模板见 [实验记录模板](../../templates/experiment_record.md)。原始生成物不提交 Git。
- PR 合并后仍可处于未验收；适用测试/联调及非作者审核完成后才更新结论。第一周补证状态仍维护于 [Week1 验收表](../week1/week1_acceptance.md)，不混写为本周实现成果。
- W2-A01–A09 通过且包含真实 EP→Vidur 回写，才判定本周完成。仅 mock 通过标为部分完成。unsupported 的能力必须明确边界，不因其他配置成功而宣称覆盖。
