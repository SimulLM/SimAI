# 校准策略与数据分层

## 目标

高精度必须被量化，而非由功能数量或单次运行结果证明。每个校准场景至少记录：输入、模型/拓扑、软件和子模块版本、随机种子、仿真值、参考值、绝对误差、相对误差、P95/P99 误差（如适用）与运行成本。

## 第一周公开参考：DeepSeek profile-data

第一周就使用 [deepseek-ai/profile-data](https://github.com/deepseek-ai/profile-data) 的公开 V3/R1 PyTorch Profiler trace，生成计算与通信重叠的基线事件表。该仓库提供训练、Prefill 和 Decode trace；README 说明推理 Prefill 使用 EP32、TP1，Decode 使用 EP128、TP1，并采用均衡 MoE 路由。

### 可以校准的内容

- Prefill 与 Decode 中计算、AllToAll 和等待事件的顺序；
- 计算—通信重叠比例与关键事件的持续时间占比；
- 固定 EP 配置下的通信阶段、等待点和关键路径结构。

第一周交付物必须包括 Prefill/Decode 的关键事件表：事件名称/类别、开始时间、持续时间、并行关系、通信组规模、已知配置和数据来源。后续开发以该事件表约束任务图与通信结果接口；“仿真输出与 trace 的系统化误差评估”留在通信闭环实现之后。

### 不能据此宣称的内容

- 端到端 TTFT、TPOT、P95/P99 时延或服务吞吐的绝对准确度；
- 专家负载偏斜、跨节点网络拥塞或真实请求到达负载下的行为；
- 对 DeepSeek 线上系统硬件、RDMA、拓扑或调度策略的完整复刻。

## 资源分层

| 阶段 | 所需资源 | 用途 |
|---|---|---|
| M1–M2 | Linux CPU 环境 | 解析模式、SimCCL、Vidur、固定 trace/工作负载和小规模 ns-3 基线 |
| M3–M4 | 按需单机 GPU | AIOB 或真实框架算子画像、计算模型与 KV/batch 行为校验 |
| M5 | 多节点 GPU + RDMA（按需申请） | EP AllToAll、网络竞争、PD KV 传输与端到端指标的真实对照 |

单机 GPU 不能验证 EP32/EP128 的跨 GPU、跨节点 AllToAll/RDMA 网络行为。因此在通信闭环与测量方案成熟前，不租用 GPU 服务器；优先使用公开 trace 和 CPU 仿真推进开发。

## 结果报告规则

每张实验图必须说明参考数据来源、比较层级、误差公式、未建模因素和运行成本。若某项结果仅与公开 trace 的事件结构一致，应表述为“行为校准”，不得表述为“端到端精度验证”。
