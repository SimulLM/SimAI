# DAG shared first-token diagnostic

This is an explicit opt-in runtime patch, not the default simulator, a frozen fee or pristine SimAI. `BATCH_FIRST_TOKEN_COSTS` points to a JSON object of input_length:batch_size keys and positive finite host-interval seconds; `BATCH_FIRST_TOKEN_TRACE` names a new trace. Supply the bootstrap to the DAG CLI in place of `-m vidur.main`. The existing PD config must use `decode_pull_candidate` and zero single-request `consumer_first_token_host_s`. Missing shapes fail. One task is charged per selected group after all KVs are ready and before Decode; the task models inclusive host/GPU wait as GPU occupancy, an unverified approximation. It has not been tested under all races or failures. Do not use it as a production model or a same-fee baseline comparison until those limitations and the independent batch fee contract are resolved.

`baseline_bootstrap.py` is a separate fixed-group diagnostic that requires the readiness-corrected baseline checkout; it delays enqueue until every explicitly listed request reaches its modeled KV-ready time, then charges one explicit synthetic interval. It does not reserve a Decode GPU and only supports one preselected group; unexpected IDs fail. It is neither an unmodified original baseline nor a natural concurrent scheduler.
